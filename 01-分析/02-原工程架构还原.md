## 2. 架构约定（注释原文提炼，最值钱的部分）

### 2.1 启动顺序是硬约束

> 「场景配置最终写进 `01-shared.js` 的三个全局对象 `oi` / `Mn` / `en`。
> 各模块**只在创建时读它们**（有的还会克隆一份），
> 所以 `selectGameMap` 必须在任何模块创建之前调用，
> `99-boot.js` 的启动函数 `QC` 第一件事就是调它。」

**含义**：配置是"快照式"读取，不是响应式。换地图必须重启或在创建前切换。
这是个明确的设计取舍 —— 简单、可预测，代价是运行时不能热切配置。

### 2.2 地图注册机制

```js
var gameMaps = {}, activeGameMap = null, defaultGameMapId = "frost";
function registerGameMap(id, definition) { definition.id = id; gameMaps[id] = definition; return definition; }
function selectGameMap(params) { /* 按 params.map 查表，找不到则报错并回退默认图 */ }
function captureGameMapScene() { /* 把当前 oi/Mn/en 拍成一份配置，避免两处数字不一致 */ }
function gameMapPropText(key, fallback) { /* 道具/枪身文字按当前地图取，缺省回退港口图 */ }
```

- 地址栏 `?map=port` 切港口图，不带参数默认 `frost`（霜脊站）。
- 找不到登记名时 `console.error("[maps] 没有登记名为 … 的地图…")` 并回退，**不是静默失败**。
- `captureGameMapScene()` 从运行时拍快照，避免"配置写两遍对不上"。

### 2.3 变体机制（不是复制整个模块）

> 「别的地图要不同的天空时：在场景配置里写 `sky.style = "名字"`，并用 `registerSkyStyle` 登记一份变体。
> 变体可以提供：`fragmentShader` 整份天空片元着色器顶替 `H6`；`patchVolumetric(源码)` 改写体积雾着色器。
> 场景配置里另有 `sky.envScale` 和 `post`（覆盖后处理的调参表）。
> 没有写这些的地图走的完全是原来的代码和数值。」

**这是整套架构最漂亮的一点**：新增一张地图 = 写配置 + 登记变体，不用 fork 渲染代码。
注释还解释了 `post` 的具体理由（雪地平均亮度比港口高一个量级，测光目标亮度要从 0.12 抬高，否则雪会被压成灰色）——
**参数为什么这么定，都写清楚了**。

### 2.4 着色器按地图条件编译

> 「下面的着色器片段都包在 `SL_SNOW` 里，只有打开积雪的地图才给材质加这个定义，
> 港口图编译出来的着色器**不含它们**。积雪只加在按世界坐标取样的材质上；
> 三平面材质（枪、手、敌人）是会动的东西，不加。」

**含义**：用编译期宏而不是运行时分支，避免每帧判断，也避免无关地图付出着色器开销。

### 2.5 碰撞与寻路是可验证的

> 「结构的碰撞盒（墙、楼板、踏步、平台、栏杆、立柱、舱段）是**走查路线和多层寻路验证过的**，
> 位置和大小不要动。」
> 「梯道建的时候会沿线探一遍碰撞盒，对不上的记在 `G.physics.nav.layered.problems`」

**含义**：关卡数据不是"看着差不多就行"，有自动走查（`walktest` / `navtest`）当验收门禁，
改错了**不会悄悄出问题**，会被记进 problems。这是工程化思维。

### 2.6 其它约定

| 机制 | 说明 |
|---|---|
| 事件总线 `Dy()` | `Map<事件名, 回调数组>`，`on` 返回取消订阅函数，`off` / `emit` 齐全 |
| 全局状态 | `window.__G = { THREE, params, map, events, rng, time:{t,dt,frame,real}, quality }` |
| 确定性随机 | `rng: il(+(params.seed \|\| 4207))` —— 固定种子可复现 |
| 画质档位 | `low/medium/high/ultra`；`zy()` 判 UA / `maxTouchPoints` / `WEBGL_debug_renderer_info` 自动降级 |
| URL 参数 | `map / seed / q / bench / shot / show / noaudio / autostart`；`#bench` 等效并强制关音频/自动开始 |
| 设置持久化 | `YC()` 读 / `Wf()` 写 `localStorage`，`try/catch` 包住（隐私模式下不崩） |
| 致命错误 | `bM()` 写 `window.__fatal` + `console.error("[fatal]")` + 向 `#app` 插一个 `#fatal` 元素上屏 |
| 截图/展示 | `__setShot` 支持 `ui:0/1`（隐藏界面）、`weapon:0`（隐藏武器）、`peace:1`（清敌人） |
| 日志规范 | 统一 `[模块名]` 前缀：`[boot]` `[maps]` `[fatal]` `[audio]` `[load]` `[level]` `[frost]` … |

## 3. 可直接搬进「网上寺庙」的目录骨架

```
src/
├── 01-shared.js          场景配置（尺寸/光照/天气/文案/材质参数），只在创建时读
├── 02-render.js          渲染器、画质档位、后处理、天空
├── 03-mats.js            材质库（木/石/瓦/纸/苔），着色器补丁按场景条件编译
├── 04-physics.js         碰撞盒、漫游约束
├── 05-props.js           程序化器物、匾额/碑刻装饰贴图（纯装饰，非经文）
├── 06-level.js           庭院灰盒
├── 07-backdrop.js        远景（山、林、云）
├── 08-ground.js          铺装、苔痕、水面
├── 10-audio.js           Web Audio 环境音（风/雨/檐铃/脚步）
├── 12-player.js          漫游控制（第一人称 + 触屏），**无射击**
├── 16-game.js            体验流程（漫游节点、导览、收集）
├── 30-maps.js            场景注册表 selectScene / registerScene
├── 40-temple-*.js        具体寺院场景，按构件拆分（参照 47 号 5 文件做法）
├── 44-nav-layers.js      多层寻路（台基/回廊/二层）
├── 60-walktest.js        自动走查验收
├── 99-boot.js            启动、URL 参数、事件总线、__G、错误兜底
└── ui/ui.css             设计 token + HUD + 触控 + 减动效
dist/
└── index.html            构建产物：全内联、零外链、断网可玩
```

**命名沿用数字前缀的理由**：加载顺序一目了然，天然表达依赖方向（大号依赖小号），
也方便构建脚本按文件名排序拼接。这套约定和参考件一致，后续对照阅读成本低。
