## 第一档 · 零耦合，直接照搬

### 1.1 工程约定

| 资产 | 参考实现 | 本项目落地方式 |
|---|---|---|
| 数字前缀分层 | `01-shared` → `02-render` → … → `99-boot` | `src/NN-xxx.js`，加载顺序即依赖方向 |
| 配置快照 | 各模块**只在创建时**读 `oi/Mn/en`，有的克隆一份 | `01-shared.js` 导出不可变配置对象 |
| 启动顺序约束 | `QC()` 第一句调 `selectGameMap()` | boot 首句注册并选定场景，之后才创建模块 |
| 注册表 + 回退 | `registerGameMap(id, def)` / `selectGameMap(params)`，找不到**明确报错并回退** | 场景/天气预设同样机制 |
| 变体而非分支 | `registerSkyStyle()` 提供 shader / `post` 调参覆盖 | 不同殿堂、不同时段用变体登记，不改渲染主逻辑 |
| 条件编译 | `SL_SNOW` 宏，无关地图不编进着色器 | 雨/雪/雾效果按场景开关编译 |
| 事件总线 | `Dy()` 的 `on/off/emit`，`on` 返回取消订阅函数 | 模块间禁止直接互调内部函数 |
| 全局上下文 | `window.__G = { params, map, events, rng, time, quality }` | 统一运行时状态，便于调试 |
| 确定性随机 | `rng = il(+(seed \|\| 4207))` | 固定种子复现画面与问题 |
| 自动走查验收 | `60-walktest` / `61-navtest`，问题记入 `problems` | 场景可通行性当验收门禁，改错不静默 |
| 日志规范 | `[boot]` `[maps]` `[fatal]` `[audio]` 等统一前缀 | 便于过滤定位 |

### 1.2 调试与运行能力

| 资产 | 参考值 | 备注 |
|---|---|---|
| URL 参数 | `map` `seed` `q` `bench` `shot` `show` `noaudio` `autostart` | `new URLSearchParams(location.search)` 读取，纯本地 |
| 基准模式 | `?bench` 或 `#bench` → 强制 `noaudio=1` + `autostart=1` | 一键跑性能 |
| 画质档位 | `low` / `medium` / `high` / `ultra` | `zy()` 判 UA、`maxTouchPoints`、`WEBGL_debug_renderer_info` 自动降级 |
| 设置持久化 | `YC()` 读 / `Wf()` 写 `localStorage`，`try/catch` 包裹 | 隐私模式不崩 |
| 致命错误 | `bM()` → `window.__fatal` + `console.error` + 页面插 `#fatal` 元素 | **绝不白屏** |
| 截图开关 | `__setShot` 的 `ui:0/1`、`weapon:0`、`peace:1` | 便于做宣传图/自动化截图 |
| 移动适配 | `viewport-fit=cover`、安全区 CSS 变量 `--sat/sab/sal/sar`、`is-touch` 类、`prefers-reduced-motion` | 触屏摇杆 + 减动效 |

### 1.3 UI 设计系统（**有现成原文**）

`../04-数据/参考原件-内联CSS.css` 是 31 KB 的**未混淆 CSS 原文**，可读性远好于 JS。

| 资产 | 内容 |
|---|---|
| CSS 变量 | 23 个：`--ink` `--ink-2` `--bone` `--bone-dim` `--bone-faint` `--signal` `--signal-hot` `--rust` `--steel` `--alarm` `--line` `--plate` `--plate-solid` `--f-display` `--f-label` `--f-mono` `--sat` `--sab` `--sal` `--sar` `--gl` `--gr` `--shadow` |
| 分区注释 | `tokens · page + boot · HUD · radio · touch controls · menus · panel · motion preferences` |
| HUD 组件 | objective tracker、wave warning、crosshair + hit marker、damage direction、interaction prompt、kill feed、health（仅受伤时显示）、world-space objective diamonds、radio subtitles |
| 高频类名 | `menu` `btn` `h-wm` `is-touch` `h-tape` `h-cross` `h-hit` `h-prompt` `m-actions` `loc-card` `h-ammo` `slider` `toggle` 等（完整表见 `CSS设计token与类名.md`） |

> 建议：**只取 tokens + 布局骨架 + 动效偏好处理**，HUD 组件按寺庙题材重做（导航提示、场景说明、静观计时），
> 不要连 crosshair / kill feed / ammo 一起搬。

## 第二档 · 拆包改造，真正的引擎骨架

| 资产 | 参考实现 / 命中 | 复用方式 | 成本 |
|---|---|---|---|
| Three.js 渲染管线 | 整库内联，`WebGLRenderer` 33、`toneMapping` 56、`shadowMap` 114 | 用 npm `three` 引入，只配置需要的部分 | 低（标准做法） |
| 画质自适应 | `zy()` + 4 档 `Pr` 配置 | 照思路重写，别抄混淆代码 | 低 |
| 程序化贴图 | `CanvasTexture` 4、`DataTexture` 10、`fillText` 4、`create*Gradient` 17 | **重点复用**：木纹/石纹/瓦当/匾额/碑刻纹样全用 canvas 画出来 | 中 |
| 程序化音效 | `AudioContext` 6、`createBuffer` 8、`createGain` 3、`createBiquadFilter` 1 | 风/雨/檐铃/脚步/远处环境声；**不做诵经、法会音** | 中 |
| 内联 Worker | `Blob([hand4WorkerSource()])` + `createObjectURL`，最多 12 线程 | 单文件约束下做多线程的范式；寺庙场景若无需重计算可暂不用 | 中 |
| 漫游与碰撞 | `12-player.js` 的 `nP()` 状态对象、`04-physics.js` 碰撞盒、`Raycaster` | **去掉射击/后坐力/开镜**，保留移动、视角、重力、碰撞、触屏 | 中 |
| 多层寻路 | `44-nav-layers` / `45-frost-nav`，三层五梯道 | 台基、回廊、二层场景可用；纯漫游也可简化为碰撞约束 | 中高 |
| 天气与天空 | `55-frost-sky`（polar 变体）、`56-frost-weather`、体积雾 `patchVolumetric` | **重点借鉴**：晨昏、雨雪、雾、体积光，寺庙氛围的核心 | 高（GLSL） |
| 积雪/潮湿材质补丁 | `SL_SNOW` 条件编译、三平面材质区分静态/动态物体 | 苔痕、湿润石阶、雪后庭院可沿用同一思路 | 高（GLSL） |
| 程序化几何 | `InstancedMesh` 19、`BoxGeometry`/`PlaneGeometry`/`CylinderGeometry` | 柱列、斗拱意象、屋檐、铺装，参数化批量生成 | 中 |
| HUD / 菜单框架 | 见第一档 1.3 | 结构复用，内容重做 | 低 |

> **技术难点提示**：Shader / 3D 数学才是真正的学习成本，不是 JS 语法。
> 若你的主力栈是 Python/React/嵌入式，建议先用现成 Three.js 示例 + 简单材质跑通，
> 体积雾与自定义 shader 放到阶段 3 再上。
