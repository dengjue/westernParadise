## 1. 结论先行

| 场景 | 风险等级 | 说明 |
|---|---|---|
| **本地自用探索 / 离线原型 / 不外发** | 低 | 不「向社会公众提供」，通常不落入互联网宗教信息服务许可范围；但仍应尊重、不戏谑 |
| **发给朋友 / 小范围传阅** | 中低 | 一旦扩散就不好控制，建议内容按公开标准做 |
| **公开网站 / 小程序 / 应用商店上架 / 公开传播** | **高** | 若内容涉及宗教教义教规、宗教知识、宗教文化、宗教活动信息，**需取得《互联网宗教信息服务许可证》** |
| **含仪式模拟、讲经、募捐、功德付费** | **极高 / 不做** | 法规对非许可主体有明确禁止性规定 |

**给本项目的直接建议**：

1. 探索期产物**只在本地自用，不上线、不公开分发、不接支付**。
2. 定位严格限定为「**传统建筑与园林空间的数字展示 / 文化漫游**」，不做宗教仪式、不做教义讲解、不做募捐。
3. 若将来要公开发布，**先做合规评估再动手改内容**，不要先做完再补。

## 2. 法规依据（原文要点）

**《互联网宗教信息服务管理办法》**
国家宗教事务局令第 17 号，由国家宗教事务局、国家互联网信息办公室、工业和信息化部、公安部、国家安全部五部门联合制定，
2021-12-03 公布，**2022-03-01 起施行**。全文共 5 章 36 条。

| 条款 | 与本项目相关的要点 |
|---|---|
| 第二条 | 在境内从事互联网宗教信息服务适用本办法；范围包括**互联网宗教信息发布服务、转载服务、传播平台服务以及其他与互联网宗教信息相关的服务** |
| 第三条 | 应遵守法律法规、践行社会主义核心价值观，坚持我国宗教独立自主自办原则、坚持我国宗教中国化方向 |
| **第六条** | 通过**互联网站、应用程序**、论坛、博客、公众账号、即时通信工具、网络直播等形式，以**文字、图片、音视频**等方式**向社会公众提供宗教教义教规、宗教知识、宗教文化、宗教活动等信息**的服务，**应当取得互联网宗教信息服务许可** |
| 第六条（条件） | 申请人须为**境内依法设立的法人或非法人组织**，法定代表人/主要负责人为**中国国籍内地居民**；须有熟悉宗教政策法规与宗教知识的**信息审核人员**、健全的管理制度与信息安全制度、匹配的场所设施资金、近 3 年无犯罪记录。**境外组织或个人及其在境内成立的组织不得从事** |
| 第七条 | 许可向省级人民政府宗教事务部门申请，需提交审核人员培训情况、管理制度、栏目功能与域名等材料 |
| 第十五、十六条及其相关禁止性规定 | 除规定情形外，**任何组织或个人不得在互联网上传教**，不得开展宗教教育培训、**发布讲经讲道内容或转发链接**，**不得组织开展宗教活动**，**不得直播或录播拜佛、烧香、受戒、诵经、礼拜等宗教仪式**，**不得以宗教名义开展募捐** |
| 讲经讲道主体 | 网上讲经讲道应由取得《互联网宗教信息服务许可证》的**宗教团体、宗教院校、寺观教堂**组织开展 |

> **两个关键限定词**：
> ① 「**向社会公众提供**」—— 本地离线自用不面向公众，与公开服务有本质区别；
> ② 「**宗教教义教规、宗教知识、宗教文化、宗教活动等信息**」—— 范围相当宽，
> 「宗教文化」也在内，所以「我只是做建筑美学、不算宗教内容」这个说法**不能想当然**，
> 需要看具体呈现方式与整体观感。

## 3. 内容红线清单（本项目硬约束）

### 3.1 绝对不做

| 类别 | 具体表现 |
|---|---|
| 仪式模拟 | 上香、跪拜、礼佛、叩首、诵经/念咒计数、敲钟祈福、供灯供佛、放生、法会、受戒、洒净 |
| 募捐与付费 | 功德箱、香火钱、付费祈福、虚拟供品、以宗教名义募捐、任何引导捐赠的入口 |
| 教义内容 | 讲经讲道、教义讲解、经文引用作游戏文案、宗教知识问答/考核、宗教教育培训 |
| 占卜类 | 抽签、解签、算命、求签、测吉凶 |
| 不尊重表达 | 以宗教人物/圣像为敌人、目标、可攻击对象；戏谑、恶搞、恐怖化、血腥化；战斗/闯关/击杀机制 |
| 冒用主体 | 真实寺院名称、真实僧团/法师名义与肖像、伪造授权或背书 |
| 引流 | 跳转现实宗教场所、组织、账号、直播、社群 |

### 3.2 谨慎处理（需逐条审查）

| 类别 | 建议口径 |
|---|---|
| 匾额、楹联、碑刻文字 | 优先用**建筑/方位/年代/构件名称**等说明性文字，或无文字纯纹样；**不引用经文** |
| 陈设器物 | 作为**建筑陈设与工艺展示**，不赋予仪式功能、不加交互动作 |
| 环境音 | 风、雨、檐铃、脚步、鸟鸣等自然音；**不使用诵经、法会、唱念音频** |
| 场景命名 | 用中性空间名（前庭、回廊、后院），不用具体宗教场所实名 |
| 「游戏」定位 | 对外表述用「数字展示 / 漫游体验 / 文化空间」，避免强化宗教活动属性 |
| UI 文案 | 不出现「修行、功德、加持、祈福、开光、护佑」等词 |

### 3.3 推荐做法

- 内容主体是**空间、建筑、园林、光影、天气、材质工艺、传统纹样**。
- 玩法是**漫游、观察、导览、时段欣赏**，无对抗、无数值养成、无仪式交互。
- 全部素材程序化生成，不引用任何真实寺院的照片、图纸、录音、经文文本。
- 探索期在文件头/关于页写明「**技术探索原型，非宗教信息服务，不对外提供宗教内容**」。

## 4. 若将来要公开发布：决策路径

```
是否公开发布？
├─ 否 → 保持本地自用，遵守第 3 节红线即可
└─ 是 → 先回答三个问题
        Q1 内容是否可能被认定为「宗教教义教规/知识/文化/活动信息」？
           → 大概率会（题材决定），按「是」准备
        Q2 主体是否符合第六条条件（境内法人/非法人组织 + 中国籍内地居民负责人 + 审核人员…）？
           → 个人开发者通常不符合，需与符合条件的主体合作
        Q3 是否需要《互联网宗教信息服务许可证》？
           → 向省级人民政府宗教事务部门咨询确认，取得许可后再上线
        ⚠️ 未确认前不要上线、不要公开分发、不要接支付
```

**建议**：正式发布前咨询省级宗教事务部门及专业法律顾问；
同时与具备许可资质的宗教团体/寺观教堂沟通内容合规性。这一步不是技术工作，别让 AI 替你下结论。

## 5. 其它风险（非合规）

| 风险 | 说明 | 应对 |
|---|---|---|
| 版权 | 参考件的代码、文案、美术为他人产物 | **只借鉴架构与设计思路，不复制代码与文案**；`00-原文件` 仅本地参考，不随产物分发 |
| 商标 | 「几猫」及港口文案与本项目无关 | 全部重写 |
| 性能 | 2.87 MB 内联 JS、shader 复杂，低端机可能掉帧 | 4 档画质 + UA 降级 + 按需裁剪 Three.js |
| 可访问性 | 3D 场景对晕动症、视障用户不友好 | `prefers-reduced-motion`、可关镜头晃动、提供非 3D 文字说明 |
| 技术债 | 在混淆代码上改 = 屎山 | 遵守 `../AGENT.md` 第 3 节，源码与产物分离 |
| 数据误导 | 静态扫描 ≠ 运行时行为 | 所有结论标注口径，断网 + Network 面板复核 |
