## 2. 3.1 首个闭环：斗拱意象

1. 所有尺寸、层数、间距和材质选择进入 `01-shared/world.ts` 或 `01-shared/materials.ts`；
   `06-world` 只负责读取配置并生成几何。
2. 斗拱只作为檐下静态建筑细节，不添加交互、文本、可拾取物或额外玩法。
3. 使用 Box/Cylinder 等基础几何组合，保持低多边形和启动时一次性创建；不在主循环中重建。
4. 生成结果必须与现有柱列和屋檐对齐，不扩大玩家碰撞盒，不改变四条导览触发点。
5. 完成标准：对象命名可检查、配置递归冻结、`check:content` 零命中、`npm run verify` 全绿，
   并完成一次开发页视觉走查。

## 3. 共同约束

- 不引入外部模型、贴图、字体、音频或网络请求。
- 保持 `00` 到 `99` 单向分层，浏览器 API 只在既有允许层出现。
- 用户可见文案集中管理；自动关键词门禁不替代人工内容审查。
- 阶段 3 的新功能不回退 M1：单文件仍须可由 `file://` 打开，版本与变更记录同步更新。

1. 保留 `clear` / `mist` 的 M1 行为，在 `WeatherPreset` 中新增 `rain`；雪、体积光和连续时段插值不在本次范围。

## 8. 3.4 首个闭环：手势门控的自然声床

1. 只使用 Web Audio API 程序化合成：低通噪声作为风与远景底噪，高通噪声随雨势作为雨声，短振荡器音作为脚步与檐铃；不引入音频文件。
2. `AudioContext` 只能由第一次键盘或指针手势创建并恢复；页面加载、自动化启动和 `?noaudio` 均不得自动播放或创建上下文。
3. 音色、增益、滤波频率、循环缓冲时长、脚步间距和檐铃周期全部进入 `01-shared/audio.ts`；音频层只读取配置。
4. 天气事件只调整雨声增益；角色移动通过 `player:step` 事件触发脚步；自然声床与 M1 漫游、雨效和 file:// 单文件保持解耦。
5. 完成标准：用户手势后能听到自然声床，`clear` / `mist` / `rain` 的雨声增益可切换，`?noaudio` 保持静音，释放时断开并关闭上下文；单测与离线门禁全绿。
