## 从现有代码和画面发现的问题

| 现状与证据 | 优化判断 | 所属阶段 |
|---|---|---|
| `land/Builder.ts` 合批前统一 `toNonIndexed()` | 重复展开位置、法线和 UV，尤其球体与管线开销大；应保留索引，优先做可精确验证的减负 | P1 |
| 现有 high 全景约 55 draw calls、330 万提交三角形/帧 | draw calls 已较少，继续盲目合成一个大 Mesh 收益有限；需区分主视图、反射、阴影的重复提交 | P1、P4 |
| 全场同材质一个静态批次，叶片也覆盖整片宝林 | 近景仍可能提交镜头外的远景几何；需要分块后再做视锥裁剪与 LOD | P4 |
| 四档画质主要调整树叶、莲花及纹理分辨率，建筑细节基本相同 | 低档仍承担大量建筑几何；应按距离保轮廓、减次级细节 | P2、P4 |
| `Garden.ts` 树高、叶片、莲花共享一个随机序列 | 切换画质改变叶片抽样次数，后续树木与花朵布局也会漂移；需拆分稳定随机流 | P3 |
| 莲叶为平面，树冠分布和远景楼阁重复明显 | 增加有限变体、弯曲和物种层次，保留整体秩序感 | P3、P5 |
| `Atmosphere.ts` 每帧反射，时段切换重新生成环境图 | 需要反射更新策略、反射对象筛选、环境图生成次数与显存权衡 | P4、P5 |
| 全景中水面与天空交界明显，强反光处局部细节被抹平 | 联调雾、曝光、粗糙度和高光，而非简单叠加泛光 | P5 |
| 导航高度与部分障碍仍写在 `LandCamera.ts`，游览每 16 秒切景 | 应统一可走表面数据、完善路径镜头与暂停恢复 | P6 |

## 统一预算与验收口径

- 同一次对比固定：生产单文件、seed、画质、光阴、CSS 视口、DPR、浏览器与设备；四景点分别采样。
- 每景点先预热 60 帧，再采样 180 帧；记录帧间隔 p50/p95、绘制调用、提交三角形、几何缓冲字节与渲染资源数量。
- 帧间隔包含浏览器调度，并受显示刷新率限制；它不是 GPU 执行时间。几何缓冲字节不等于总显存，单文件体积也不等于运行内存。
- 桌面 high 的体验目标为 p95 ≤ 16.7ms，移动 low 目标为 p95 ≤ 33.3ms；需要在明确记录的目标设备上验证，桌面触控模拟不替代手机 GPU 实测。
- 体积沿用 `build-budget.json`：目标 1.5 MiB，硬上限 2,932,900 字节。
- 每阶段交付：独立提交、实施文档回写、`npm run verify`、对应浏览器证据和最终 HTML 离线检查。
- 美术改动保留四景点同机位截图；性能优化优先保留可见轮廓、材质和光照，使用数据评估取舍。
