# Phase 4 · 空间分块与渲染预算

状态：已完成工程实现与本机验收（2026-11-13）。以 Phase 3（`5b1df68`）为基线，分支 `feat/pure-land-phase4`；真实目标手机的 30 FPS 长测仍待补验。

## 目标

使近景只承担必要的几何与反射工作，让 low 与 high 的成本差异体现到建筑、植被和像素处理全过程。

## 实施任务

1. **空间分块**：静态建筑按区块及材质合批，宝林/莲池实例按池区分组；比较 24/48 米等候选粒度，以实际收益选择。
2. **距离分级**：近景保留瓦当、衣褶、珠饰，中景保轮廓与主要脊线，远景简化构造；采用滞回阈值避免边界来回切换。
3. **反射分级**：单独控制反射可见层与几何细节；静止时限频，镜头/光阴改变时及时失效，避免缓存倒影跟不上镜头。
4. **反射正确性**：主相机与反射相机分别评估可见性；水纹时间持续推进，缓存只减少场景重绘。
5. **后期预算**：检测实际渲染尺寸、MSAA、HDR 目标和泛光 mip 的成本；手机优先控制像素填充率，再决定是否保留后期。
6. **自适应策略**：使用连续超预算区间与恢复滞回调整分辨率/反射，尊重用户手动固定画质；避免每几帧切档造成视觉呼吸。
7. **资源生命周期**：区块/LOD/反射目标的归属明确，共享几何去重释放，重复挂载和画质切换后资源计数回稳。

## 预算与取舍

- 分块增加 draw calls，但应减少近景提交三角形与不可见像素；同时衡量两项，不能只优化一个数字。
- 目标：代表近景的提交三角形减少至少 30%；全景 p95 无持续回退；low 在目标手机达到 30 FPS 档位目标。
- CPU 提交时间、帧间隔、GPU 时间分开记录；GPU 计时扩展不可用时明确缺项。
- 反射更新率由实验确定，测试静止、快速转头、光阴切换和水岸斜视四类场景。

## 本轮实施拆解

1. 静态构件按包围盒中心分到 24/48 米候选网格，再按材质合批；完整构件归属一个区块，保留跨边界包围体，避免切开屋面或台阶产生裂缝。
2. 屋顶和三座造像建立近/中/远资产，按相机距离与滞回选级；近景保持当前精修等级，中远景减少瓦当、发髻珠粒与背饰采样。缓存阴影使用固定中档副本并共享几何，避免 LOD 改变后留下过时阴影。
3. 植物实例按稳定 ID 分池区：树叶按叶序号交错排列，距离抽样仍覆盖每棵树；莲花/莲叶保持全部中心，只改变曲面细分。每档共享矩阵、颜色及风属性，不在帧间重传实例。
4. 主相机、反射相机分别选择 LOD 和视锥；阴影代理置于独立阴影层。反射沿用 Three 的反射相机与裁剪数学，静止时限频，镜头/投影/光阴/目标尺寸改变时立即重绘；缓存期间水纹与风时间继续推进。
5. 统一初始化与 resize 的后期渲染尺寸，记录实际目标/MSAA/泛光 mip 预算。自动画质才启用持续超预算降分辨率与缓慢恢复，显式 URL/已记忆画质锁定；阈值集中配置。
6. 增加提交耗时和可用时的异步 GPU 查询；分开报告帧间隔、提交耗时、GPU 时间、反射帧占比和资源数量。补齐共享资源去重释放及策略/几何/相机独立性测试。
7. 同视口采样 P3、24 米、48 米方案，保留最终四景点与三光阴近景证据；离线/触控/减动效、快速转头、反射光阴失效和循环资源检查后回写结果。真实手机 30 FPS 需真实设备补验，触控模拟只验证布局和操作。

基线产物保存在本机 `reports/phase4-baseline.html`。性能目标同时检查实际反射更新帧与缓存帧，避免仅用缓存帧的低三角形数掩盖峰值成本。

## 最终实现与取舍

### 空间、细节与反射

- 采用 **48 米**静态/植物网格。按完整构件包围盒中心归区，不裁切构件本身；几何包围体保留越界部分。主/反射相机独立裁剪。
- 屋顶距离阈值 `65 / 150 m`，造像 `65 / 135 m`，滞回 `8 m`；植物 `38 / 85 m`，滞回 `6 m`。距离从相机到包围球外沿估算，保护大型近景资产。用户画质决定最高可用细节。
- 树叶三级稳定前缀比例 `1 / 0.64 / 0.34`；排序按叶序号交错各棵树，远景不会只剩区块中的部分树。莲花/莲叶保持全部实例中心。矩阵、颜色、风属性共享，距离切级不上传实例。
- 固定 far 的远景楼阁回归区块合批，不为永远不升级的资产创建逐件 LOD；高档全景更新帧 calls 从初稿 `995` 降至 `671`，代价是包围体变宽后多提交少量远景几何。
- 可变 LOD 的阴影采用共享中档几何的固定副本；冠团代理只进入 shadow 层。远档屋面同样保留底面，反射/仰视不出现透空屋顶。
- 主视图 / 反射 / 阴影层为 `0 / 1 / 2`。`DistanceLod` 继承 `Object3D`，避免 Three.js 先命中 `isGroup` 而跳过 `isLOD.update`；每个相机保留独立滞回状态。
- 反射完整沿用原生 Reflector 的镜面矩阵与斜裁剪。low/medium/high/ultra 静止上限 `15 / 20 / 24 / 30 Hz`，实测 high 约 `20.8 Hz`（帧时量化影响）；镜头、投影、光阴与目标尺寸变化立即失效。水纹/风时钟照常推进；减动效下只在失效时重拍。

### 像素与生命周期

- high 后期像素比上限 `1`，ultra `1.25`；整数像素尺寸统一用于初始化、resize 和缩放，修复首次 HDR 目标与 bloom mip 尺寸不一致。low/medium 无后期目标。
- 自动模式连续 `>25ms` 达 `2.4s` 后降 `0.1`，最低 `0.7`；连续 `<17ms` 达 `10s` 后恢复，切换冷却 `6s`，`>150ms` 的暂停不累计。URL/本地已记忆画质锁定，自动选择不再写成手动记忆。
- high 在 `1601×997` 下 HDR 主目标为 `1601×997`、MSAA 配置 2，计入双目标与 bloom mip 的附件估算 `126,652,880 B`；768² 反射估算 `7,077,888 B`。这是附件格式估算，**不是总显存实测**，未包含默认帧缓冲、环境图、阴影与驱动开销。
- 自动策略集成测试中，scale `1→0.9→1`：主画布 `2401×1495→2161×1345→2401×1495`，后期 `1601×997→1440×897→1601×997`，反射 `768→691→768`。该测试注入持续帧事件，验证装配逻辑，不当作真实设备自动降档性能数据。
- 去重释放共享几何/材质/贴图，另外释放 InstancedMesh 的实例缓冲、Reflector 几何与异步查询。销毁 canvas 时归还 WebGL 上下文；dispose 可重复调用。仅 `?debug/?bench` 提供 `dispose/restart` 回归入口。

## 性能结果

### 采样口径

生产单 HTML；同一 macOS / Tabbit Chromium 156，CSS `1601×997`、DPR `2`、seed `20261113`、dusk、普通动效；high 主画布比 `1.5`，low 为 `1`。每景点预热 60 帧、采样 180 帧，显式画质锁定自适应。

- 提交三角形含该帧全部渲染 pass；稳定采样不含光阴切换时的一次性阴影/环境图生成。
- `submissionMs` 包装最外层 `renderer.render`，累计同步 JS 提交区间，嵌套倒影不重复计时；`pipelineCpuMs` 另含后期编排与查询开销。该墙钟耗时也会受调度/驱动等待影响。
- GPU 使用 `EXT_disjoint_timer_query_webgl2`，4 个异步查询槽，满时跳过、不等待，disjoint 丢弃。报告回收到的 GPU 样本，不能按同一帧强行匹配倒影类别。P3 原产物没有此埋点，GPU 对比项为空。
- 原始数据保存于本机 `reports/`，不入 Git。最终表取 `phase4-merged48-{high,low}.json`，同轮基线为 `phase4-baseline-repeat-{high,low}.json`。

### 24 / 48 米选择与 p95 回退

- 初稿的 24 米方案裁剪更细，但 calls 和 CPU 提交成本更高；复测还发现固定远景楼阁逐件 LOD 是冗余提交，随后合回区块。
- 合回后，high 全景 24 / 48 米更新帧为 `1,183 / 671` calls，主殿为 `545 / 388`；24 米主殿三角形 `848,654` 比 48 米更少，但该轮全景 p95 `33.4 / 16.6ms`，提交 p95 `30.9 / 12.1ms`。因此选择 48 米，接受一定额外几何，优先压住提交开销。
- 同轮 P3 / 最终 P4 high 全景 p95 为 `16.7 / 16.6ms`。此前 P3 的 `25.2ms` 回退本轮没有持续复现。中间重复采样 CPU p95 与部分机位帧间隔波动明显，保留报告；不能宣称稳定的整体 FPS 或 GPU 百分比加速。
- high 静态几何驻留 `38,538,684→43,771,388 B`（36.75→41.74 MiB，**+13.58%**），用于保留三级近景资产；low `33,149,884→28,827,620 B`（31.61→27.49 MiB，**-13.04%**）。共享实例缓冲仍为 `1,675,944 / 823,584 B`，未因三级 LOD 翻倍。
- `scene.instances` 是所有 LOD 描述对象的 count 总和，不能当实际唯一植物数；缓冲字节按共享 BufferAttribute 去重。实际花心、莲叶、树木中心保持 P3 布局。

## 验收证据

- **工程**：22 个测试文件 / 121 用例；涵盖完整构件跨区包围体、视锥裁剪、相机独立 LOD/滞回、固定 far 合批、植物实例保存与共享、反射失效、自动预算锁定/恢复、目标整数尺寸、查询池与 disjoint、资源去重释放。`npm run verify` 检查类型、分层、内容、lint、格式、测试、双构建与离线断言。
- **画面**：P3/P4 high 四景点同机位对照；立面、檐下、造像、莲花 × 晨/昼/暮共 12 张近景；完整近景瓦当、衣褶、莲瓣与珠饰保留。固定远景重新合批后继续通过四景点与步行回归。
- **反射**：24 次快速切换的下一绘制帧均更新；三时段、投影变更即时失效；主视图与倒影选级不同且互不污染；静止存在更新帧与缓存帧。循环四轮四景点及光阴后，稳定为 `494` 几何、`35` 纹理、`26` programs（首次编译阶段除外）。
- **生命周期**：同一文档四次真实 restart，启动稳定为 `403` 几何、`35` 纹理、1 canvas、17 个跟踪的 window/document 监听器；双次 dispose 后几何/纹理/canvas/监听器均为 `0`，上下文确认归还。UI high/low 连续切换后数量也回稳。有限循环验证不替代真机长测。
- **减动效**：121 帧两端直接读取 WebGL 画布，`1,596,197` 个非黑像素，差异 `0`；静止倒影更新 `0` 次。投影与光阴改变仍各自触发刷新。
- **离线与操作**：CDP 对当前页禁网，`file://` 加载、四景点、环境音 running、自动游览换景、中轴步行至殿内 `z=-44.07, y=5.70`、画质选择均通过；HTTP(S) 请求与运行错误均为 `0`。
- **触控模拟**：`390×844` / DPR 2、low，无页面溢出；左右触区移动与环顾生效。四视角 p95 帧间隔 `9.3 / 9.4 / 9.3 / 9.3ms`，GPU p95 `2.52 / 2.67 / 1.94 / 1.81ms`；这是桌面 GPU 触控模拟，**不能作为手机 30 FPS 证明**。
- **降级**：无 WebGL 有可见说明与重载按钮；上下文丢失有提示并停循环；历史庭院 `?scene=courtyard` 可启动。
