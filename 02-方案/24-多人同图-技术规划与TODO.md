# 多人同图 · 技术规划与 TODO

> 决策：第一版用 WebSocket + 附近同步，不用 P2P。服务器不渲染、不模拟完整场景。仅做本机及受控协作者原型；公开上线须先走 [风险与合规评估](03-风险与合规红线.md)。

## 1. 第一版体验

- 先用 `courtyard` 小庭院验证：每个主动加入的浏览器会话一个匿名角色，刷新或重连可获得新角色，房间有独立人数上限。上限初始 30，仅作本机测试配置，不是已验证的容量。
- 自己仍以现有控制器移动；看得到附近角色的走动、转向与离场。角色无互相碰撞。不做账号、昵称、聊天、交易、排行榜或共享任务；场景时段和天气仍是个人状态。
- 只有开发环境显式加入才开始联网；连接失败回到独自漫游。原有 `file://` 单文件和默认静态站不建立连接，场景资产继续由浏览器加载和缓存。
- 小庭院闭环通过后，再评估大世界坐标、飞行校验与分区加载的结合；服务器不知道材质、渲染分区或角色模型。

## 2. 实现约定

| 部分 | 职责 |
| --- | --- |
| 浏览器 | 采集本地角色位置和朝向；按网络节拍上报；远端模型复用几何与材质，按快照插值；断开后清空远端模型 |
| 房间状态 | 每连接一个服务端 ID，内存管理在线角色；只接受本连接更新；校验序号、有限数值、坐标范围、移动速度和消息频率 |
| 广播 | 每 100 ms 最多一轮；按 XZ 网格找候选，再按 XZ 距离筛；进入半径 18 m、离开半径 22 m，单客户端最多 15 个邻居 |
| 运维 | 实时服务与静态构建分开；开发阶段仅监听回环地址。对外测试前另行配置同源 WSS、来源校验和受控访问，不保留位置历史 |

首版协议使用小型 JSON 消息，服务端使用单调时钟。客户端发 `move`（递增 `seq`、`x/y/z`、弧度 `yaw`），服务端发 `welcome`（分配 ID）、`snapshot`（服务端递增 tick、新增或变化的角色、移出角色 ID）或满员拒绝。快照有序；不把自己的角色回发。实现到传输层时须限制帧大小和待发送队列；慢连接不能无限积压。

位置是客户端上报的；基础校验只能拦住明显异常，不承诺阻止穿墙，也不记录真实身份。来访者只看到附近角色，不拿全图位置或其他客户端网络地址。

### MP1 验收记录

- 角色从庭院配置出生点起步，`yaw` 规范化到 `[-π, π]`；水平速度和发送频率分别使用令牌桶，高度仅检查庭院合法区间。客户端若脱离同步后要重连，应回到出生点再重新加入；第一版不承诺异地恢复。
- 270 项测试全部通过；类型、分层、内容门禁、改动文件 lint / 格式检查及站点、离线单文件构建通过。离线产物静态校验通过，浏览器断网与联机走查留在 MP3。
- `npm run verify` 的全仓 lint 被未改动的 `05-宣发/tools/make-github-shot.mjs` 和 `05-宣发/tools/render.mjs` 各一条 `no-unused-expressions` 错误阻塞；本阶段未夹带修复。

### MP2 验收记录

- `npm run dev:multiplayer` 启动独立进程，监听 `ws://127.0.0.1:8787/multiplayer`，只接受本机 Vite 默认端口的浏览器来源。不接受局域网连接；来源检查不是身份认证。
- 单条上行文本消息限 512 B；每 15 秒探活，未响应则在下一轮断开；连接发送积压超过 32 KiB 时断开，避免跳过增量造成状态失步。
- 275 项测试通过，其中 5 项使用本机真实 WebSocket，覆盖两个连接同步、第三个满员拒绝、断开释放席位、来源拒绝，以及二进制、畸形 JSON 和超大消息。慢连接极限、长时间心跳和 30 人容量尚未压测。
- 站点和单文件正常构建，单文件静态断言通过。MP2 验收时前端尚未接入。

### MP3 前端接入约定

- 开发页使用 `http://127.0.0.1:5173/?scene=courtyard&multiplayer=1` 显式加入。线上构建、`file://`、非庭院场景和没有开关的页面都不建立联机连接。
- 加入期间暂留出生点，最多等待 3 秒。联机状态显示在庭院 HUD；满员、服务不可达或断开时清空远端角色并保留本地漫游，无自动重连。刷新重新从出生点进场。
- 本地输入不等待服务器确认；每 100 ms 最多上报一条有变化的姿态。远端复用庭院角色的几何与材质，用服务端增量做短时插值；减少动效模式直接应用姿态。共享出生点可能导致刚进场的角色重叠，无玩家间碰撞。

### MP3 验收记录

- Chrome headless 双独立实例通过键盘输入分别移动：双方均渲染一个远端角色，停下时观察坐标与对方本地坐标差小于 4 cm；离场、重新加入、服务停机降级、服务不可达降级可复现。截图与数据位于 `/tmp/opencode/courtyard-mp3-fwtEwR/`。
- 同一轮验证默认庭院不建立多人 WebSocket；正式单文件以 `file://` 打开，在模拟断网且带联机参数时仍可键盘移动，CDP 未观察到 HTTP(S) 或 WebSocket 请求。
- 281 项测试通过，包括新增的客户端节拍、协议顺序、超时/满员、远端插值与资源复用测试。类型、分层、内容、改动文件 lint/格式、双产物构建与单文件静态校验通过；全仓 `verify` 仍受 MP1 记录的两条旧 lint 错误阻塞。双实例走查不是 30 人或设备性能结论，下一步为 MP4。

### MP4a 局域网入口

- `npm run dev:multiplayer:lan -- <本机私网 IPv4>` 单独启动测试入口：Vite 只绑定指定地址的 `5173`，通过同源 `/multiplayer` 转发至仅监听回环的房间服务。拒绝通配、回环、公网或未分配给本机的地址；默认本机命令和正式构建不变。
- 只在受信任的局域网使用，不做公网端口映射。来源校验不是鉴权，连接不加密；停止测试进程即关闭入口。
- 本机通过实际网卡 IP 验证了 HTTP、浏览器联机状态、同源 WebSocket 双连接的移动/离场和非法来源拒绝。282 项测试通过；站点和单文件构建及离线静态校验通过。不同设备间的 Wi-Fi、防火墙和触屏体验仍需现场验证。

### 独立测试服务器

- `qu3` 作为受信任的局域网测试服。单独构建可联机站点，静态网页与房间共用一个私网端口；不在服务器上运行 Vite，不修改防火墙或系统级服务。
- 通过 SSH 上传版本目录，由用户级服务切换版本。上线检查 HTTP 和 WebSocket；失败恢复上一版。重启会断开当前房间。普通站点和离线单文件不启用联机。
- 首次部署已完成，地址 `http://192.168.100.25:5173/?scene=courtyard&multiplayer=1`。从开发机验证了静态资源、浏览器联机和 WebGL 画布、源码不可访问、双连接移动与离场、错误来源拒绝。回滚逻辑尚未在测试服故意触发；手机和电脑实际游玩仍待走查。开发机的临时局域网入口已停止。
- `scene=courtyard` 仅为旧庭院联机验证入口。正式主体验仍用 `/`，第三人称用 `/?cam=third`，不会降级到旧地图；真正面向玩家的多人验收以精修主场景接入为前提。
