# 多人同图 · 技术规划与 TODO

> 决策：第一版用 WebSocket + 附近同步，不用 P2P。服务器不渲染、不模拟完整场景。仅做本机及受控协作者原型；公开上线须先走 [风险与合规评估](03-风险与合规红线.md)。

## 1. 第一版体验

- 先用 `courtyard` 小庭院验证：每个主动加入的浏览器会话一个匿名角色，刷新或重连可获得新角色，房间有独立人数上限。上限初始 30，仅作本机测试配置，不是已验证的容量。
- 自己仍以现有控制器移动；看得到附近角色的走动、转向与离场。角色无互相碰撞。不做账号、昵称、聊天、交易、排行榜或共享任务；场景时段和天气仍是个人状态。
- 只有开发环境显式加入才开始联网；连接失败回到独自漫游。原有 `file://` 单文件和默认静态站不建立连接，场景资产继续由浏览器加载和缓存。
- 小庭院闭环通过后，再评估大世界坐标、飞行校验与分区加载的结合；服务器不知道材质、渲染分区或角色模型。

## 2. 实现约定

| 部分 | 职责 |
| --- | --- |
| 浏览器 | 采集本地角色位置和朝向；按网络节拍上报；远端模型复用几何与材质，按快照插值；断开后清空远端模型 |
| 房间状态 | 每连接一个服务端 ID，内存管理在线角色；只接受本连接更新；校验序号、有限数值、坐标范围、移动速度和消息频率 |
| 广播 | 每 100 ms 最多一轮；按 XZ 网格找候选，再按 XZ 距离筛；进入半径 18 m、离开半径 22 m，单客户端最多 15 个邻居 |
| 运维 | 实时服务与静态构建分开；开发阶段仅监听回环地址。对外测试前另行配置同源 WSS、来源校验和受控访问，不保留位置历史 |

首版协议使用小型 JSON 消息，服务端使用单调时钟。客户端发 `move`（递增 `seq`、`x/y/z`、弧度 `yaw`），服务端发 `welcome`（分配 ID）、`snapshot`（服务端递增 tick、新增或变化的角色、移出角色 ID）或满员拒绝。快照有序；不把自己的角色回发。实现到传输层时须限制帧大小和待发送队列；慢连接不能无限积压。

位置是客户端上报的；基础校验只能拦住明显异常，不承诺阻止穿墙，也不记录真实身份。来访者只看到附近角色，不拿全图位置或其他客户端网络地址。

## 3. 开发顺序与验收

| 编号 | 状态 | 交付和验收 |
| --- | --- | --- |
| MP1 | [x] | 房间与协议核心：容量、加入/离开、非法坐标和乱序校验、速度预算、网格与附近角色增删；无浏览器和网络依赖，7 项单测覆盖 |
| MP2 | [x] | 本机 WebSocket 服务：来源、消息大小、心跳和背压；已用真实连接验证同步、满员及断线清理 |
| MP3 | [ ] | 接入 `courtyard`：显式开发入口、角色插值、连接提示和断线回退；两浏览器实际走查，同时复验单文件无外部请求 |
| MP4 | [ ] | 分散和大殿拥挤各跑 2 / 10 / 30 客户端；记录进程 CPU/RSS、出入站字节、快照节拍 P95、断线和前端帧率，再决定房间上限、拆房或优化 |
| MP5 | [ ] | 仅当实测显示服务端下行是主要瓶颈时，评估更紧凑的编码或 WebRTC 直连 + WebSocket 回退；不让玩家接力转发 |

记录真实链路流量，不拿 JSON 负载估算当实测。重点比较稀疏、聚集和进出可见范围的场景；满员或断线时，单机漫游必须仍可用。

### MP1 验收记录

- 角色从庭院配置出生点起步，`yaw` 规范化到 `[-π, π]`；水平速度和发送频率分别使用令牌桶，高度仅检查庭院合法区间。客户端若脱离同步后要重连，应回到出生点再重新加入；第一版不承诺异地恢复。
- 270 项测试全部通过；类型、分层、内容门禁、改动文件 lint / 格式检查及站点、离线单文件构建通过。离线产物静态校验通过，浏览器断网与联机走查留在 MP3。
- `npm run verify` 的全仓 lint 被未改动的 `05-宣发/tools/make-github-shot.mjs` 和 `05-宣发/tools/render.mjs` 各一条 `no-unused-expressions` 错误阻塞；本阶段未夹带修复。

### MP2 验收记录

- `npm run dev:multiplayer` 启动独立进程，监听 `ws://127.0.0.1:8787/multiplayer`，只接受本机 Vite 默认端口的浏览器来源。不接受局域网连接；来源检查不是身份认证。
- 单条上行文本消息限 512 B；每 15 秒探活，未响应则在下一轮断开；连接发送积压超过 32 KiB 时断开，避免跳过增量造成状态失步。
- 275 项测试通过，其中 5 项使用本机真实 WebSocket，覆盖两个连接同步、第三个满员拒绝、断开释放席位、来源拒绝，以及二进制、畸形 JSON 和超大消息。慢连接极限、长时间心跳和 30 人容量尚未压测。
- 站点和单文件正常构建，单文件静态断言通过。当前前端仍是单机；下一步 MP3 才能用两个浏览器在庭院里互相看到角色。
