## 1. 决策依据：C 不是否定 B，是把 B 工程化

路线 B 的正确内核是「**源码与产物分离**：可读多文件源码 + 构建时内联成单 HTML」。
C 保留这个内核，只把实现手段从「自写拼接脚本 + 原生 JS」升级为标准工具链：

| 长期维护的刚需 | B 的自写方案 | C 的标准方案 |
|---|---|---|
| 类型安全 | 无，靠约定和 JSDoc | TypeScript `strict` + `@types/three` |
| 依赖方向可控 | 靠人自觉，无自动检查 | 分层编号 + `scripts/check-layers.mjs` 自动门禁 |
| 可回归 | 断网手工打开 | Vitest 单测 + 产物断言，进 CI |
| 可重复构建 | 自写脚本拼接，顺序敏感 | Vite/Rollup 依赖图，`package-lock.json` 锁版本 |
| 开发体验 | 改一次跑一次脚本 | HMR、source map、错误定位到源文件 |
| 多人协作 | 弱 | ESLint/Prettier 统一风格、MR 门禁 |

**代价**：起步多一层工具配置、依赖体积与 Node 环境要求。
对「探索期一次性原型」不划算，对「长期维护、要迭代内容、可能多人接手」是必需投入。

**C 必须守住 B 的两条结论**：
1. `dist/single/index.html` 仍是**零外链单文件**，可微信转发、断网双击可玩；
2. 所有素材**程序化生成**，不引入贴图/模型/音频/CDN/远程字体，这是离线能力的物理基础。

## 2. 分层架构：数字前缀 + 单向依赖

沿用参考件 `01-shared … 99-boot` 的分层思想，但按本项目域重新划分。
**编号即依赖等级：只能依赖编号更小的层，禁止反向依赖。**

```
层级   目录                职责                                      允许依赖
─────────────────────────────────────────────────────────────────────────
00    00-types/           类型、接口、事件映射（纯声明，零实现）      无
01    01-shared/          配置常量、文案表、注册表、画质档位定义      00
02    02-core/            事件总线、时钟、随机数、日志、致命错误      00, 01
03    03-platform/        环境探测、URL 参数、画质决策、本地存储      00–02
04    04-engine/          Three 渲染器封装、场景上下文、主循环        00–03
05    05-materials/       程序化材质/纹理（CanvasTexture 等）         00–04
06    06-world/           场景构建：几何、光照、天空、天气            00–05
07    07-systems/         输入、漫游、碰撞、交互、音频（玩法层）      00–06
08    08-ui/              DOM HUD、CSS 设计系统、无障碍兜底           00–03
98    98-diagnostics/     bench、探针、自动走查钩子                   00–08
99    99-boot/             唯一装配层：创建依赖、接线、启动             全部
```

### 依赖规则（由 `scripts/check-layers.mjs` 自动强制）

1. **低层不得引用高层**：例如 `02-core` 里出现 `04-engine` 的 import 直接失败。
2. **同层可互引，但禁止循环依赖**；脚本用 DFS 检测环。
3. **跨层只能走目录入口**：写 `@/04-engine`，不写 `@/04-engine/internal/RendererImpl`。
   内部实现改动不应波及其它层。
4. `00-types` 不得 import 任何 `src` 内模块（纯声明层）。
5. 只有 `99-boot` 允许引用**所有层**并负责 new / 装配；其余层不得自行创建全局单例。
6. `window` / `document` / `localStorage` 只允许出现在 `03-platform`、`08-ui`、`98-diagnostics`、`99-boot`；
   `00–02` 必须保持纯函数/可测，这是单测不需要 DOM 环境的前提。

> 规则 6 是刻意设计：把浏览器 API 隔离到边缘，核心逻辑可在 Node 里直接跑测试。

## 3. 模块契约

| 约束 | 做法 |
|---|---|
| 模块入口 | 每层 `index.ts` 显式 re-export，对外只暴露稳定 API |
| 事件通信 | `00-types/events.ts` 定义 `AppEventMap`，`EventBus` 泛型约束事件名与载荷；**禁止裸字符串事件** |
| 配置 | `01-shared/config.ts` 全部 `as const` + `Object.freeze`，模块只在初始化时读取；**禁止硬编码坐标/颜色/时长到逻辑** |
| 文案 | 集中在 `01-shared/copy.ts`，便于逐条过合规审查；禁止散落在渲染代码 |
| 资源生命周期 | `04-engine` 统一 `dispose()` 出口，几何/材质/纹理必须登记后释放，防长时间运行内存增长 |
| 主循环 | 固定步长累加器 + 渲染插值；循环内**禁止**创建对象/数组/闭包、禁止 DOM 查询与纹理重建 |
| 错误 | 致命错误上屏 + `window.__fatal`，不允许白屏；错误边界在 `99-boot` |
| 禁用写法 | 运行时 `eval`、动态拼 `src` 加载资源、`innerHTML` 拼未转义文本（见 `../AGENT.md` 3.1） |

### 运行时上下文（对齐参考件设计，重新实现）

参考件的 `window.__G = { THREE, params, map, events, rng, time, quality }` 思路保留，
但改为**类型化、只读、按需暴露**：

- `__G` 只在开发模式与 `?debug=1` 下挂载，生产单文件默认不暴露内部对象；
- `?seed=` 固定随机数种子、`?quality=low|medium|high|ultra`、`?bench`、`?smoke` 由 `03-platform` 统一解析；
- 画质决策 = URL 指定 > localStorage 记忆 > 设备能力探测（WebGL 版本、移动端 UA、`prefers-reduced-motion`）；
- `prefers-reduced-motion` / 无 WebGL / 触屏 / 低端机四类兜底必须有明确用户可见提示，不静默降级。

## 4. 构建体系：双产物

| 命令 | Vite mode | 产物 | 用途 |
|---|---|---|---|
| `npm run dev` | development | 内存 | HMR 开发 |
| `npm run build` | production | `dist/site/` | 多文件，将来可部署静态站 |
| `npm run build:single` | single | `dist/single/index.html` | 全内联，离线可分发、可微信转发 |

`build:single` 的关键配置（由 `vite.config.ts` 按 mode 切换）：

- `base: './'` —— 相对路径，`file://` 直接打开不失效；
- `cssCodeSplit: false` —— CSS 必须并入单一 `<style>`；
- `assetsInlineLimit` 调大 —— 任何资源都不产生独立文件；
- `viteSingleFile()` 插件 —— 把 JS/CSS 内联进 HTML，移除 modulepreload 等外链；
- **单 chunk 的保障落在校验而非配置**：Vite 8 / Rolldown 默认 `codeSplitting: false`，
  天然只产出一个 chunk；`inlineDynamicImports` 在该版本会被忽略并打印 WARN，故不配置。
  一旦将来升级导致拆分，产物会多出 `<script src>`，`verify-single` 的零外链断言立即失败。

**体积预算**（`src/01-shared/build-budget.json` 为单一数据源，TS 配置与 Node 校验脚本共读）：
目标 1.5 MiB，硬上限 2,932,900 字节（参考件实测体积）。
2026-11-12 工程底座阶段实测单文件 **549,981 字节 / 0.525 MiB**，约为参考件的 19%，
主因是冒烟场景只用到 Three.js 一小部分；M1 场景落地后需重新观察。
Three.js 按需 `import`（不整库引入）是首要优化手段；超标时先裁未用模块，
**不压缩源码可读性**。体积与 MD5 由 `verify:single` 输出到 `reports/single-build.json`
（该目录不入库）—— 构建产物每次都会变，把 MD5 手抄进文档必然腐化。

## 5. 质量门禁

| 命令 | 检查内容 | 失败后果 |
|---|---|---|
| `npm run typecheck` | `tsc --noEmit`，strict + 额外严格项 | 阻塞 |
| `npm run lint` | ESLint（typescript-eslint），禁 `any`、禁未处理 Promise | 阻塞 |
| `npm run format:check` | Prettier 一致性 | 阻塞 |
| `npm run test` | Vitest 单测（`02-core` / `03-platform` 纯函数为主） | 阻塞 |
| `npm run check:layers` | 单向依赖 + 循环依赖 + 浏览器 API 越界 | 阻塞 |
| `npm run check:content` | 源码与文案中的宗教红线词扫描 | 阻塞 |
| `npm run verify:single` | 产物零外链断言、体积/MD5 报告 | 阻塞 |
| `npm run verify` | 以上全部 + `build` + `build:single` | CI 与本地统一入口 |

设计原则：**门禁脚本零第三方依赖**（只用 Node 内置模块），避免门禁本身变成维护负担。

`check:content` 的价值：把 `03-风险与合规红线.md` 的「绝对不做」清单转成可执行断言
（上香/跪拜/诵经/功德/募捐/抽签/祈福等词），防止后续迭代无意加回红线内容。
它只做**关键词提示**，不替代人工合规审查 —— 口径不可混淆。

### CI

`.gitlab-ci.yml`（工蜂基于 GitLab CI）单阶段 `verify`：`npm ci` → `npm run verify`，
`dist/single/index.html` 与 `reports/` 作为 artifact 保留一周。
本地 `npm run verify` 与 CI 跑的是**同一条命令**，杜绝「本地过、CI 挂」。
若工蜂未启用 Runner，本地门禁仍完整可用，CI 文件不影响开发。

## 6. 测试策略

| 层 | 测什么 | 方式 |
|---|---|---|
| `02-core` | EventBus 订阅/退订/异常隔离、RNG 同种子确定性、Clock 步长 | Vitest 纯函数 |
| `03-platform` | URL 参数解析与非法值兜底、画质决策矩阵、能力探测输入 | Vitest 纯函数（不依赖 DOM） |
| `01-shared` | 配置冻结、注册表行为 | Vitest |
| `scripts/` | 分层门禁能抓到故意构造的反向依赖 | Vitest fixture |
| 产物 | 零外链、`<script src>` 为 0、体积预算 | `verify:single` 断言 |
| 渲染 | 像素正确性、断网实玩、移动端、帧率 | **人工验收**，不搞脆弱的截图断言 |

2026-11-12 实测：**6 个测试文件 / 53 个用例全绿**，全部无需 DOM 环境。
其中门禁 fixture 19 例同时覆盖「故意违规必须被抓到」与「合法写法不得误伤」两个方向 ——
后者决定门禁能不能长期留在项目里，比单纯堆覆盖率更重要。

覆盖率建议：`00–03` 核心层行覆盖 ≥ 90%，整体 ≥ 70%；探索期不为了数字写无意义测试。

## 7. 版本与协作

- 版本：`0.x.y` 表示探索期；M1 可跑通后升 `0.1.0`；每次有用户可见变化写 `CHANGELOG.md`。
- 提交信息：中文、`类型: 简述`，类型限定 `feat / fix / refactor / docs / test / build / chore`。
- 分支：`main` 受保护，功能改动走短生命周期分支 + 工蜂 MR；禁止直接 force push。
- 依赖升级单独一个 commit，附 `npm audit` 结果与验证记录，不与功能改动混在一起。
- `package-lock.json` 必须入库；`node_modules/`、`dist/`、`reports/` 不入库。

## 8. 合规落地（技术侧能自动守的部分）

| 红线 | 技术约束 |
|---|---|
| 不对外发布 | 仓库私有；无自动部署；产物只在 `dist/` 本地 |
| 零远程连接 | `verify:single` 断言无 `http(s)://` 端点、无 `<link>`/`<script src>`/`@import`/`url(http`；不接埋点、字体、分析 SDK |
| 内容不越界 | 文案集中 `01-shared/copy.ts` + `check:content` 关键词门禁 + 人工逐条审查 |
| 不冒用主体 | 场景命名用中性空间名，代码与文案不出现真实寺院/僧团/法师名 |
| 声明 | 产物关于页写明「技术探索原型，非宗教信息服务，不对外提供宗教内容」 |

> 这些是**自查手段，不是法律意见**。公开发布前仍须走 `AGENT_TODO.md` 4.6 的单独合规评估。

## 9. 扩展点（接口先定，实现放到对应阶段）

| 扩展 | 归属层 | 依赖的接口约定 |
|---|---|---|
| 场景/季相注册表 | `01-shared` + `06-world` | `SceneSpec` 注册与选择，boot 第一句选定，之后只读 |
| 天气变体 | `06-world` | `WeatherPreset` 配置 + 材质补丁钩子 |
| 程序化材质库 | `05-materials` | 统一 `createXMaterial(params)` 工厂，返回可 dispose 句柄 |
| 环境音 | `07-systems` | Web Audio 合成，**白名单仅自然音**（风雨檐铃脚步鸟鸣） |
| 导览节点 | `07-systems` + `08-ui` | world-space 目标 + 事件总线上报，文案走 `copy.ts` |
| 多层寻路 / 自动走查 | `07-systems` + `98-diagnostics` | 复用参考件思路，M3 之后再做 |
| 移动端触控 | `07-systems` + `08-ui` | 输入抽象层 `InputSource` 接口，键鼠/触屏并列实现 |

**接口先写类型、后写实现**，避免阶段推进时反复改调用方。
