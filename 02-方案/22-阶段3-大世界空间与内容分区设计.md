## 1. 空间基线与设计边界

| 项目 | 当前事实 | 设计影响 |
|---|---|---|
| 世界坐标 | 米制；北为 `-Z`、南为 `+Z`、东为 `+X` | 所有分区、入口、罗盘和地标共用该约定 |
| 当前可玩边界 | `PURE_LAND.bounds`：X `[-88, 88]`、Z `[-104, 110]`，约 `176 × 214m` | 现有内容作为中心核心区保留，不整体缩放 |
| 当前可走面 | `PURE_LAND.paths` 与 `sampleLandHeight()` 描述有限路径、台阶及障碍；边界矩形不等于整块可走地面 | 新区域必须同时设计地面、路径、碰撞和导航，不能只铺大平面 |
| 当前分块 | 静态建筑和植物按 `LAND_RENDER.cellSize = 48m` 分组，支持裁剪/LOD | 48m 是新世界分块候选，不代表已有异步加载、卸载 |
| 当前远景 | 部分装饰几何延伸到可玩边界之外 | 远景轮廓不计入可探索范围、导航区域或飞行边界 |
| 当前移动 | 步行配置 `6m/s`、飞行配置 `9m/s`；第三人称操作手感尚未人工确认 | 路程耗时先按当前值计算作对照，不据此冻结最终移动速度 |

## 2. 已授权灰盒基线（最终尺度待验证）

用户授权将**有界 3 × 3 网格**作为灰盒实施基线；这不代表最终世界尺寸已冻结：

- 总边界：X/Z 均为 `[-360, 360]`，即 `720 × 720m`，是当前核心区宽度的约 4.1 倍。
- 每个分区：`240 × 240m`；以 48m 为候选渲染 cell 时，每区为 5 × 5 个 cell，全图最多 15 × 15 = 225 个 cell。
- 中心分区边界为 X/Z `[-120, 120]`；当前可玩范围完整落在其中，周边预留约 10–32m 的衔接带。
- 分区表中的内容主题仅表达空间功能，具体建筑与景观素材仍需单独设计；不以增大坐标替代可探索内容。

          ├────────────┼────────────┼────────────┤

          ├────────────┼────────────┼────────────┤

          └────────────┴────────────┴────────────┘

## 3. 路线与尺度检查

### 地面路线

- 主路线以当前南侧出生点为起点，先连接中心庭园主要构件，再通过四个正交门户接入相邻分区。
- 相邻网格分区均有一对坐标完全一致的门户；内侧八区至少接入两个邻区，中心区接入北/南/东/西四区。
- 次级环线连接外围分区，提供不必折返中心的路线；角区通过相邻边门户接入，不要求穿越中心。
- 每个主路线分叉处有可辨认地标或方向提示；初步目标是主路线相邻导航线索不超过约 120m，需在灰盒走查中修订。
- 道路、水岸、桥和可走面必须跨区连续；区域边界不能改变地面高度、碰撞半径或地表语义。

### 路程量级（候选布局推算）

- 3 × 3 分区中心间距为 240m。按当前步行速度 `6m/s`，单次中心到中心约 40 秒；按飞行速度 `9m/s` 约 27 秒。
- 穿越整张地图的几何下限约 720m，完整多区主游览路线（起终点可不同）暂按约 1.9–2.2km 规划；对应当前速度约 5.3–6.1 分钟步行。
- 上述只是基于配置速度和网格长度的估算，不是实测体验。阶段 1/2 手感未确认前，不据此调速或宣称游览时长达标。
- 灰盒阶段需要记录路线实际长度、可见地标间距、步行/飞行所需时间，以及转向/边界处的迷失点；如果路径空洞，优先缩小或重排区域，不盲目加面积。

## 4. 区域元数据与共享坐标契约

每个分区由 `src/01-shared/landRegions.ts` 中的稳定元数据描述；本阶段只落实灰盒需要的字段，完整内容密度和资产清单留待后续：

| 字段 | 约束 |
|---|---|
| `id` / `bounds` | 稳定 ID 与米制 X/Z 轴对齐边界；分区边界不重叠，门户边界相接 |
| `seedKey` | 由世界 seed、分区 ID、资产类别和稳定局部 ID 派生；增加一株植物不能改变其他区域布局 |
| `neighbors` / `portals` | 邻区 ID、共享门户坐标、通行宽度、地面高度和允许的步行/飞行状态；两侧描述必须一致 |
| `routes` | 稳定路线 ID、中心线/宽度、表面类型、坡度和导览节点；作为导航与可走面定义的共同来源 |
| `landmarks` | 稳定 ID、坐标/可见范围、显示名和所属区域；不以“最近中心点”替代区域边界判定 |
| `contentProfile` | 区域功能、近/中/远景职责与密度目标；不在元数据里塞入渲染对象实例 |

实现约束与当前兑现范围：

1. 灰盒渲染、地面高度、碰撞和导航共用 `LAND_WORLD` 的世界坐标及分区 ID；区域音景尚未接入分区。
2. 当前中心区—东区门户 `(120, 83)` 与东向路线及分区边界对齐；其余门户仍是布局契约，不代表已有道路/门洞。
3. `resolveLandRegionSeed(worldSeed, regionId)` 由稳定 `seedKey` 派生 32 位区域 seed；当前灰盒构件是固定配置，不含随机资产布局。
4. HUD 按区域边界确定区域、再独立取最近地标；保留核心区原有子区域标签。
5. 飞行继续使用阶段 2 的 42–64m 高度带，但第三人称水平边界只扩至本次灰盒范围；扩建高地/树冠前仍需重新定义高度与禁入体积。

## 5. 分块、接缝与近中远景约定

- 48m cell 作为优先验证候选；240m 分区含 25 个 cell。当前 `LAND_RENDER.cellSize` 和 `Builder` 的静态分组是预构建裁剪，不足以证明运行时分区加载/释放。
- 阶段 3 原型使用全图西北角 `(-360, -360)` 作为稳定原点；第三人称下静态建筑、LOD 子构建器、植被与东区灰盒均按该原点分组。默认第一人称继续沿用旧构建配置，不改变其场景入口。
- 完整建筑、桥、树冠等资产整体归属一个 cell，不沿 cell 边界切几何；包围体可跨界。道路/水岸等连续表面通过共享边界采样保证接缝一致。
- 内容职责先按距离层划分：近景保留可交互/可辨结构；中景以共享实例和简化构件维持轮廓；远景只承载地标剪影与空气透视。阶段 3 不指定未经设备测量的显存/纹理预算。
- 原型先验证中心区与一个邻接区跨界往返、快速转向、步行/飞行切换和回看接缝；之后才决定 24/48m 或分层网格是否适用。

## 6. 阶段 3 灰盒原型范围与退出条件

按用户授权的候选布局，阶段 3 只实现最小可判定原型：

1. 建立区域描述和可复现 seed；中心 `core-court` 沿用当前内容，不做大规模重建。
2. 只新增一个代表性邻区（优先 `east-water-court`），包含连续地面、跨界主路、一个远近层次明确的地标和简化水岸。
3. 在同一坐标契约下跑通区域分类、导航标签、步行碰撞和飞行边界；确认门户两侧无地面/视觉断缝。
4. 用固定路线验证当前 48m cell 的归属与跨区包围体；不实现异步加载器、资源池或批量内容生成（属于阶段 4）。
5. 保留离线单文件、固定 seed 和现有场景默认入口；用明确的 `?cam=third` 原型入口隔离新增第三人称体验。

当前实现范围：第三人称模式装配 25 个 48m 地面 cell（或诊断候选 100 个 24m cell）、跨区南侧路径、东侧池面/石岸/步桥/观景台与低矮外缘；其余七区不生成。场景仍同步完整构建，没有运行时异步加载/卸载。

退出阶段 3 前必须有：

- [x] 用户授权 720m / 3 × 3 候选作为灰盒原型基线；最终全图尺度仍需按游玩密度与设备数据复核。

## 7. 明确不做与待确认项

- 不把九个分区一次性做满，不扩展战斗、任务、排行、交易或仪式交互。

- 不移动现有出生点，不改变默认相机/控制模式，不以桌面模拟替代真实手机验收。
- 720 × 720m 是获得授权的原型基线，尚未经过用户手感、内容密度或目标设备性能验证，不是最终地图承诺。
- 灰盒之外的其余七区仍只是空间职责草案，尚未批量实现；最终区域密度、飞行高度和移动速度仍需后续原型/设备验证。
