## 1. 阶段目标与当前事实

阶段 4 在阶段 3 的 48m 稳定 cell 坐标契约上，验证“按角色/相机位置和朝向请求 cell、有限并发构建、离开活动半径后回收本地资源”。实现需继续保持离线和第三人称入口隔离。

当前事实：

- 核心庭园与植被 LOD 仍按既有路径一次构建；东侧水院仅在第三人称角色步行/飞行时由 cell 调度器按需装配。
- `prioritizeLandCells()` 是纯规划函数：近区需求不受朝向影响，视线前方远区可预取，输出数量有硬上限。
- `LandCellQueue<T>` 限制并发/待处理请求、按优先级启动、同 key 去重，并支持排队/运行中取消；晚到结果会释放而不重新挂回。载荷由调用方提供，队列不创建场景对象或调度 GPU 工作。
- `SharedResourcePool<T>` 用幂等 lease 维护同步创建资源的引用计数；最后一个租约释放才 dispose，pool 关闭时尽力释放全部资源。
- `LandCellResourceScope` 先释放 cell 独占载荷，再归还共享 lease；销毁异常时继续清理剩余项。
- `createEastRegionCellPayload()` 已将 scope 接入东区灰盒：地面/游线按 cell 拆分，池/桥/观景台按锚点归属；每个 payload 只持有本 cell 几何，材质仍由世界级材质所有者管理。
- 默认第三人称灰盒路径改由 `EastRegionCellStream` 管理：角色步行/飞行姿态每 120ms reconcile，队列并发最多 2、待处理最多 14、需求计划最多 16 格；退出步行/飞行模式后卸载驻留 cell。
- 构建许可在同步更新批次内合并，每批最多放行一个同步 cell factory，避免固定步追赶时累积 permit；factory 仍在主线程同步执行。该节流不是毫秒耗时预算、Worker 或无卡顿保证。
- 上述半径、时间与预算均为原型常量，未通过真机校准。`createEastRegionPrototype()` 保留为测试/静态样本适配器；运行时路径使用独立 payload 和有界调度器。本机 headed Firefox 已做实时路线及部分观景矩阵抽查；移动/飞行状态下的完整流式视觉矩阵、目标设备帧时与设备预算仍未验收，不能称为“流式加载已验收”。
- 阶段 3 的一次性 headless SwiftShader 对比只作布局参考，不代表真实 GPU/设备性能。预取距离、活动半径、并发数和驻留上限均未冻结。

## 2. 实施顺序

### 4.1 需求优先级规划（核心实现完成）

- 输入只包含稳定 cell key、中心点和 X/Z 平面相机姿态，不读取全局浏览器对象。
- `activeRadius` 内的 cell 属于 `active`；更远但处于 `prefetchRadius` 且方向点积不低于 `minimumForwardDot` 的 cell 属于 `prefetch`。
- `frontBias` 仅调整同级优先顺序，不能突破半径；`maxCells` 是返回计划的硬上限。
- 重复 key、无效坐标、无效朝向和同分排序必须确定；参数无效立即报错。
- 单测覆盖视线前方/后方、快速转向输入、重复候选、硬预算上限与错误配置。

### 4.2 可取消、去重与有限并发队列（第三人称原型已接入）

- 已实现状态 `queued / loading / ready / error`，同 key loading/queued 请求合并；排队任务可提升优先级。
- `maxConcurrent` 与 `maxPending` 有硬上限；满队列时只允许更高优先级任务替换最低优先级的排队任务。
- `unload()`/`dispose()` 对 queued、loading、ready 状态均幂等处理；loader 接收 `AbortSignal`，忽略取消并晚到成功的值会由注入的释放函数回收。
- 错误状态可观察，同 key 可再次请求重试。低成本轮廓/fallback、取消加载期间保留旧画面等用户体验策略尚未与渲染层集成。
- `EastRegionCellStream` 将规划结果交给队列，并在 payload ready 且仍处于需求集时挂入场景；旋转/移动导致 cell 离开计划时取消排队/运行请求或释放 ready payload。
- 加载器同步执行几何构建；stream 在每个同步更新批次至多发放一个构建许可，但尚无毫秒级逐帧构建预算或 Worker。“有限并发”本身只约束队列任务数。

### 4.3 资源所有权与卸载（通用租约与东区 payload 集成完成）

- 已实现 `SharedResourcePool<T>` 的同步共享资源创建、按 key 去重、引用计数 lease、幂等 release 与 pool 关闭清理。
- 销毁回调抛错时仍继续尝试清理其余 entry；之后抛出首个错误。释放失败/重复释放有自动化断言。
- 已实现 `LandCellResourceScope`：对本地 disposer 逆序执行，再释放去重后的共享 lease；销毁错误不阻断其余清理。
- 东区 payload 通过 scope 注册合批几何、水面和池岸几何；卸载会先从父组移除，再释放独占几何，不 dispose 世界共享材质。
- `LandBuilder` 的 primitive 几何改为按需创建，避免每个 cell builder 都分配未使用的圆柱/球体模板。
- 卸载先解除场景/LOD/碰撞/导航引用，再释放 chunk 本地资源；销毁操作幂等。
- 取消、切后台、WebGL 丢失、卸载与重新进入均要覆盖；不得让旧异步结果在新一轮生命周期重新挂回。
- 第一人称既有场景保持原路径；初次集成仅在 `?cam=third` 的东区灰盒启用。

### 4.4 场景集成与验证（原型调度已接入，本机实时验收部分完成）

- 东区 cell factory 已支持独立创建和释放；48m 布局为 25 个 cell，24m 测试布局为 100 个 cell。运行时仅第三人称入口启用姿态驱动队列，第一人称路径不变。
- 当前原型 active 半径为 `1.5 × cellSize`、前向预取半径为 `3 × cellSize`、方向点积阈值 0.1；这些不是冻结的设计/设备预算。
- Headless 固定步长路线与本机 headed Firefox 实时 RAF 路线均已覆盖东行、折返、cell 装配/卸载；本机另完成右键转向、42m 飞越东区/莲池/观景台、飞行往返与安全落地、tab blur/focus、dispose/restart。Firefox 160 与 Chrome 157 均通过真实 WebGL context 丢失/同页恢复 smoke；Chrome 默认第一人称模式也确认恢复后可继续移动。差分确认按需出现的莲花/宝树 geometry 是核心区静态构件，不是东区 cell 残留；东区多机位与快速步行折返也已 smoke。下一步转向匹配设备/A4、B0 与原生 C0 验收。
- 每轮记录活动/排队/加载/回收 cell 数、并发峰值、生成耗时、几何/纹理数量、绘制 calls 与卸载后回稳；不把浏览器估算显存当作真实 GPU 驻留。

## 3. 验收门槛

阶段 4 只有同时满足以下条件才可关闭：

- 快速转向、跨 cell、飞越、往返没有持续空洞、明显闪烁或地面裂缝。
- 加载/排队/活动和驻留资源均受配置硬上限约束，取消和重复请求不会造成重复构建或泄漏。
- chunk 本地资源卸载后计数回稳；共享资源多 chunk 并存/释放顺序变化时不提前销毁、也不重复 dispose。
- 离线单文件、默认第一人称路径、页面暂停/恢复及阶段 3 导航碰撞回归通过。
- 真实设备/A4/B0/C0 按原有解除条件独立验收，不由 headless 结果替代。
