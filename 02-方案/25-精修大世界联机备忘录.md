# 精修大世界联机交付备忘录

### 第十一批：暂停续游与导览可访问性

1. 游线可暂停并继续；暂停时不记录到站，同标签页刷新保留暂停状态和已确认站次。
2. 预览中可展开每站观景说明，便于出发前了解观察方向。
3. 到站、暂停和完成提供离散读屏通知；确认下一站后焦点保持在可用控件上。

### 第十批：游线重游与状态说明

1. 已确认过站点后提供重新游览按钮，重置本标签页站次并保留正常角色位置。
2. 展示已确认完成的站数，以及当前目标站之后的路段距离；明确不含走到当前站的距离。
3. 地图补齐颜色图例、当前站可读描述及地面/飞行状态；飞行箭头只表示水平位置。

### 第九批：游线示意图

1. 展开游线站点时显示北向上的等比例示意图，编号对应站点顺序，标出当前站。
2. 用低频导航事件更新自己的位置和朝向；超出图幅明确提示，不把边缘位置当实际位置。
3. 在窄屏/低高度布局限制导航详情高度并允许滚动，保留收起入口。地图仅在本机绘制，不增加房间消息。

### 第八批：莲池游线与导览内容

1. 补齐东侧三站游线；用角色移动算法验证两段均可走通。
2. 地面到站展示针对本站的观景提示，飞过不触发。
3. 站点预览给出每段与全程的水平参考距离，区分路线长度与实际步行里程。

### 第七批：支线、续游与预览

1. 西侧宝林游线沿南侧横向步道前往西廊，再向北进入林畔；沿用地面到站判定。
2. 同标签页刷新后恢复目的地和已确认的站次，不保存角色坐标或房间编号；自由游历清除进度。
3. 游线提供可折叠的站点预览，区分已完成、当前与待游；不改变移动或联机状态。

### 第六批：个人游览导览

1. 第三人称导航卡可选择目的地，使用已有可步行点，显示相对当前朝向的方位和水平直线距离。
2. 区分地面抵达和从空中经过；在到达范围边缘避免反复提示。
3. 提供一条中轴逐站游线，手动走到每站再继续；可随时取消。不移动镜头、不传送、不向伙伴广播个人导览选择。

### 第五批：手机控制与取景

1. 设置中可互换移动盘与环顾盘位置，升降键跟随环顾侧；不改变输入轴方向。
2. 设备本地记住用户手动选择的触控布局、联机导航展开状态；未选择时保持原有默认值。
3. 隐藏界面时清除触控盘、飞行键与临时通知，保留恢复按钮；恢复后继续当前房间。

### 第四批集中交付

1. 在联机详情列出附近伙伴，按临时编号排序，人数不变但角色更换时也刷新。
2. 从名单选择导航目标，目标离场/超出同步范围时自动回到最近伙伴；断线不保留旧目标。
3. 画质菜单支持恢复自动档，清除手动偏好和两个 URL 别名，保留联机和时段设置。

### 第三批集中交付

1. 大世界房间发布包含自己的在线人数；人数变化才补发，不暴露远端角色位置。
2. 在线人数大于一但附近无伙伴时，导航详情指向共同的南侧入口；回到附近后恢复伙伴方向。
3. 大世界网址指定的画质仅对当前页面生效；在设置中主动选择才写入设备偏好，并保留联机、时段等参数。

### 房间基线的复跑方法

```sh
./node_modules/.bin/esbuild scripts/benchmark-land-room.mjs --bundle --platform=node --format=cjs --outfile=/tmp/opencode/benchmark-land-room.cjs
```

把生成的 `.cjs` 复制到测试机临时目录，用 Node 22 执行。脚本仅在回环随机端口创建独立房间，不占用在线测试服；每组一个房间进程，模拟客户端在另一个进程。玩家聚在入口或实际走到相隔 70 米的两组位置，再以 10 Hz 连续移动约 10 秒。上下行按 socket 读写字节计算（含 WebSocket 帧，不含 IP/TCP 链路开销），CPU 为房间进程的单核百分比，RSS 为采样结束时驻留内存。P95 是客户端收到相邻增量快照的间隔，不是 RTT；没有可见邻居则不应持续收到快照。该测试不渲染画面，不能据此宣称手机可流畅运行 30 人。

### qu3 验收记录（2026-11-22）

部署 `3dbecdc`，285 项测试通过。局域网观察端看到了同一 ID 起飞、在 42 米高度水平移动 3 米、降回地面。单测覆盖超速升降、越过高度上限和低空不合理平移的拒绝。

### 手机帧率走查

双端人工反馈：已看到两个角色，并确认双方可以各自独立控制。当前玩家之间没有碰撞体，可以穿过彼此；这是与地图碰撞分开的交互设计项。此反馈不等于已验收长时间联机、镜头或触控手感。

后续交互：精修大世界采用轻量地面避让。服务端在入口附近选择空闲可走点，并在入场消息中下发脚底坐标。客户端只限制自己走向附近地面伙伴的位移，不推开对方；允许从已有重叠中退开，空中角色不挡路。沿用原有地形分轴碰撞和联机位置上报，不做服务器物理模拟。

`d2fdc71` 已部署 qu3，287 项测试通过。双 Chrome 实际入场分别在 `(0,85)`、`(2,85)`；一人朝另一人持续走，停在相距 1.1 米处；侧移后可绕过，对方坐标没有改变。本次验证为局域网一动一静的地面场景，不是高延迟下的强一致碰撞。

**首份真机结果（2026-11-22，用户截图）：iPhone 12 Pro / Safari**。入口低画质自测，截图可见缓冲区 390×699；0 → 5 → 15 → 0 个本地陪测角色分别为 **56.9 / 56.6 / 55.9 / 56.9 FPS**，四组 P95 帧间隔均为 **21.0 ms**。15 人较初始少 1.0 FPS，离场恢复基线。此记录仅覆盖该机短时入口渲染；长时温升、真实网络和触控手感待测。原截图的坐标 HUD 遮挡部分结果，自测页改为隐藏该卡片。

单设备自测约定：专用 `?cam=third&crowdcheck=1` 页面使用固定入口机位，本地生成 10 Hz 陪测快照，复用真实远端角色的渲染和插值，不向房间发包。依次测 0/5/15/0 个角色，完整窗口结束后显示可截图的对照表。这个入口测设备渲染，不替代多人网络或触控手感走查。

部署 `a7286c8` 后从开发机 Chrome 使用手机视口（low、390×844）访问 qu3，四段均正常结束，得到 59.4 / 59.1 / 59.4 / 59.4 FPS；同时指定 `multiplayer=1` 时仍观察到零次 WebSocket 建连。这是自测流程验收，不是手机实测数据。

测试站使用 `?cam=third&multiplayer=1&framecheck=1`。仅在已联机游历、页面前台时采样；分别记录无人、有人同行和空地混合场景的连续 10 秒平均 FPS、P95 帧间隔、附近角色数、画质与缓冲区大小。附近角色数是客户端已加载的邻居数，并不保证全部在视锥内。转向让同伴进入画面再截图，附手机型号和浏览器。桌面触屏模拟仅作流程检查。
