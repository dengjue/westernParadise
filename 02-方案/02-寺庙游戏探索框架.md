## 1. 先定边界，再谈玩法

参考件是一个 FPS（射击、敌人、波次、撤离）。**这套玩法机制整体不适用于本项目**：
把宗教场所做成战斗场景、把圣像或宗教人物做成敌人/目标，既不尊重，也踩合规红线。

所以本项目要复用的是它的**技术外壳**（离线单文件、程序化场景、天气音景、漫游碰撞、HUD），
**内容内核需要重新设计**。

### 一句话定位建议

> 「一个可离线漫游的**传统建筑与园林空间**数字展示：看光影、听风雨、读建筑、慢慢走。」
> 关键词：**文化空间 / 建筑美学 / 静观氛围**，不是宗教活动、不是游戏闯关。

## 2. 玩法候选（按与红线的距离排序）

| # | 方向 | 核心体验 | 复用参考件的能力 | 合规风险 | 实现难度 |
|---|---|---|---|---|---|
| ① | **自由漫游 + 光影时序** | 在庭院/回廊/殿前随意走动，晨→午→暮→夜光照变化，雨雪雾随时间段切换 | 漫游碰撞、天空变体、天气 shader、画质档位 | 低 | 中 |
| ② | **建筑导览 / 空间叙事** | 走到特定位置弹出建筑构件说明（台基、柱列、斗拱意象、屋檐、铺装），纯知识性 | world-space 目标标记、交互提示、字幕 HUD | 低 | 中 |
| ③ | **园林与四季** | 同一空间四种季相、天气系统、植物与水面，偏"数字盆景" | `CanvasTexture` 程序化材质、`InstancedMesh`、噪声 | 低 | 中高（GLSL） |
| ④ | **静观 / 音景** | 无目标、无任务，坐着听风雨檐铃，配合呼吸节奏的柔和视觉 | Web Audio 合成、减动效、低刺激 UI | 低 | 低 |
| ⑤ | 轻量收集 / 印章 | 走遍场景收集建筑纹样图鉴、盖一枚"到此一游"式印章 | 状态持久化、HUD、目标标记 | 中低（需避免"功德/修行"式叙事） | 中 |
| ⑥ | 空间解谜 | 通过光影/方位/构件关系解开一个小机关 | 碰撞、事件总线、状态机 | 中（避免仪式化叙事） | 高 |
| ⛔ | 战斗 / 射击 / 打怪 / 副本 | — | — | **不可做** | — |

**推荐组合**：以 ① 为主线，② 为辅线，④ 作氛围底座。
首个里程碑只做 ① 的最小闭环（一个庭院 + 能走动 + 昼夜光影），用实际效果反推后续。

### 明确不做的机制（写进约束，避免后面加回来）

- 上香、跪拜、礼佛、诵经、计数、敲钟祈福等**仪式模拟**
- 功德、香火、募捐、付费祈福、供灯供佛、抽签解签、算命
- 讲经讲道、教义讲解、经文引用的文案
- 以宗教人物/圣像为角色、敌人或可交互对象
- 排行、战力、抽卡、数值养成等强游戏化系统
- 真实寺院名称、真实僧团/法师名义与肖像

## 3. 场景设计草案（纯空间，不含宗教内容）

```
                    远景：山影 / 林线 / 云
   ┌──────────────────────────────────────────────┐
   │  照壁（纹样，程序化生成）                      │
   │      ┌──────── 前庭 ────────┐                │
   │      │  铺装 / 苔痕 / 积水    │   侧院：竹、石  │
   │      │   · 光影随时间移动     │                │
   │      ├──── 台基 + 阶道 ─────┤                │
   │      │  柱列 / 檐廊（可穿行） │   回廊 → 二层   │
   │      │  格扇 / 藻井意象       │                │
   │      └──────────────────────┘                │
   │  后院：水面、石桥、落叶                        │
   └──────────────────────────────────────────────┘
```

| 层 | 内容 | 技术手段（全部程序化，无外部素材） |
|---|---|---|
| 结构 | 台基、阶道、柱列、檐廊、格扇、屋面 | `BoxGeometry` / `CylinderGeometry` / `InstancedMesh` 参数化批量 |
| 材质 | 木、石、瓦、纸、苔、水 | `CanvasTexture` 画纹样、`DataTexture` 噪声、渐变 |
| 光影 | 晨昏色温、檐下阴影、体积光、雾 | 光照配置 + 天空变体 + 条件编译 shader |
| 天气 | 雨、雪、落叶、风 | 粒子 + 材质补丁（参考 `SL_SNOW` 思路） |
| 音景 | 风、雨、檐铃、脚步、远处环境声 | Web Audio `createBuffer` 合成，**无诵经/法会音** |
| 文字 | 建筑构件说明、方位提示 | canvas `fillText` 生成贴图；文案逐条审查 |

## 5. 待决问题（需要你拍板）

| # | 问题 | 为什么现在要定 |
|---|---|---|
| Q1 | 视角：第一人称漫游 / 第三人称 / 自由轨道相机？ | 决定输入层、`12-player` 复杂度、是否要触屏摇杆 |
| Q2 | 场景规模：单个庭院闭环，还是多进院落？ | 决定关卡拆分与寻路复杂度 |
| Q3 | 有无时间推进：实时流逝 / 手动切换 / 固定几个时段？ | 决定光照系统与状态机 |
| Q4 | 是否需要移动端触屏作为 M1 必选？ | 影响输入层与 UI 布局工作量大半 |
| Q5 | 文字内容尺度：完全无文字（纯氛围）还是加建筑知识说明？ | **直接关联合规口径**，需先定 |
| Q6 | 是否计划对外发布？ | 若只是本地自用探索，合规压力小；若要公开，见红线文档第 4 节 |
| Q7 | 美术调性：写实 / 水墨写意 / 低多边形？ | 决定程序化材质与 shader 的工作量 |

> 建议先只回答 Q1、Q5、Q6 三项，其余可在 M1 效果出来后再定。

## 6. 最小闭环（M1）验收建议

- [ ] 双击 `dist/index.html`，断网可运行，DevTools Network 无外部请求
- [ ] 一个庭院，键鼠可自由走动、不穿墙、不掉出地面
- [ ] 至少 3 个时段光影明显不同（晨 / 午 / 暮）
- [ ] 一项天气效果（雨或雾）可切换
- [ ] 无任何仪式、经文、募捐、战斗元素
- [ ] 移动端可操作（若 Q4 选是）
- [ ] `src/` 分层清晰、配置与逻辑分离、关键算法有中文注释
- [ ] 单文件体积 ≤ 2.87 MB（参考件）
