## 2. A · 优先解决高画质光阴切换卡顿

### 已有证据

设备为 Apple M1 Pro / 16 GiB、Tabbit Chromium 156，CSS 1601×997、DPR 2、high 主画布比 1.5、seed `20261113`。以下是既有 P6 过渡样本，不能与预热后的 30 分钟巡游结果互相替代。

| 目标光阴 | 帧间隔 p95 / 最大 ms | 渲染管线 CPU p95 / 最大 ms | 异步 GPU p95 / 最大 ms |
|---|---:|---:|---:|
| 晴昼 | 25.0 / 50.0 | 22.3 / 41.9 | 9.90 / 15.56 |
| 落照 | 25.1 / 150.0 | 22.9 / 141.8 | 10.66 / 16.00 |
| 晨光 | 33.4 / 83.3 | 28.5 / 70.3 | 16.76 / 22.97 |

来源：`reports/phase6-lighting-high.json`。CPU 数值仅覆盖渲染管线同步区间；GPU 查询异步返回，表中分位数并非同一帧配对，不能相减后推导等待时间或直接认定瓶颈。原始 Long Tasks 已保留，但仍需与具体切换窗口、阴影/倒影更新帧关联。

### A1 采样和工具要求

1. 冷启动、首次光阴切换、完整预热后的切换分别记录。固定全境先复现，再覆盖四景点、三目标时段、连续切换和中途重定向。
2. 预热样本至少包含三组完整「晨→昼→暮→晨」循环，基线/候选交替采样，全部保留；逐轮记录 p50/p95/max、超过 33.3ms 和 50ms 的帧数、Long Tasks、绘制调用、三角形、阴影/倒影刷新次数及资源数量。
3. 性能录制与轻量验收采样分别标识，记录探针对耗时的影响；原始帧间隔采用真实 RAF 时间戳。后台或失焦造成暂停的窗口标为无效负载并保留原因。
4. 当前连接曾返回 `Profiler.enable wasn't found`。先确认可用录制通道；若仍不支持，保存错误，使用可用的分段计时和事件时间线继续缩小范围，并将必须依赖人工 DevTools 录制的结论标为待补。
5. GPU 查询不可用、disjoint 或未对应到帧时明确标识；CPU 提交耗时不等于 GPU 执行时间，Long Tasks 也不包含全部调度/GPU 卡顿。

### A4 目标与退出条件

- 同一目标桌面 high、可见且活动、完整预热后的三组有效过渡：逐组 **帧间隔 p95 ≤ 16.7ms，超过 50ms 的帧为 0**。首用/冷启动样本独立保留，记录优化是否转移了开销。
- 如果只有部分轮次达标，保留该状态与异常，继续定位；先前 150ms 样本仍保留在历史证据中。
- 四景点 × 三时段固定构图检查通过；任何像素差异说明原因，建筑与造像近景质量检查通过。
- 有行为改动时增加必要回归测试；实现交付跑 `npm run verify`，并完成最终单 HTML 禁网交互、减动效、切换/中断、四档、资源释放回归。
- 涉及调度、缓存或资源生命周期的最终候选，再做一次绑定新产物的真实 30 分钟混合长测。

## 3. B · 真实手机持续性能与操作

前置：A 的候选已固定且完成对应回归；需要实际目标手机。当前桌面触控模拟只作为布局/输入证据。

| ID | 工作 | 完成标准 |
|---|---|---|
| B0 | 确认并连接目标设备 | 记录型号、SoC、内存、OS、浏览器/版本、刷新率、屏幕/DPR、供电/低电量模式、亮度与测试环境；设备未落实时保持阻塞 |
| B1 | low / medium 短测与操作检查 | 四景点、三时段、双指移动/环顾、横竖屏、缺口/安全区、设置/说明、声音与界面恢复逐项实机验证 |
| B2 | 各拟支持档位持续 30 分钟 | 每 150 秒一段，记录帧间隔、资源、可用内存指标、设备温度/系统热状态与错误；目标各段 p95 ≤ 33.3ms，持续运行资源回稳，无崩溃 |
| B3 | 根据实机瓶颈优化并复测 | 确定每台设备推荐档位及边界；回归 A 的桌面画面/性能与相关功能，输出设备支持结论 |

采集不到的温度、内存或显存项写「不可获取」并注明工具限制；触感只作为观察描述。不能把平均 FPS、短测峰值或桌面模拟当作 30 分钟持续达标。默认优先验证 low，medium 是否推荐依据实机结果。
