# Western Paradise · 西方极乐

**一个可以自由漫游的传统建筑与园林 3D 世界。** 我们正在探索如何把建筑、空间、光影与环境声音做成轻量、可离线体验的数字漫游作品，也欢迎你一起参与建设。

[GitHub 仓库](https://github.com/dengjue/westernParadise) · [参与讨论 / 提交想法](https://github.com/dengjue/westernParadise/issues)

> 这是一个开放协作中的实验性原型，不是宗教信息或宗教仪式服务，也不代表真实寺院或宗教组织。项目仍在探索和验收中，暂不作为正式产品发布。

## 现在可以体验什么

- 漫游一座包含殿宇、楼阁、宝塔、莲池与园林的 3D 空间，欣赏晨、昼、暮光影变化。
- 使用第一人称步行、自动游览、观景点与环境音；也可体验尚在验证中的第三人称步行和飞行原型。
- 使用桌面浏览器或手机触控；项目目标之一是生成可离线运行的单文件版本。

### 本地运行

需要 Node.js 22 或更新版本，以及 npm：

```bash
git clone https://github.com/dengjue/westernParadise.git
cd westernParadise
npm ci
npm run dev
```

终端会显示本地访问地址。主要操作：WASD 移动、左键拖拽环顾（右键兼容）、滚轮缩放、H 隐藏界面；手机可用屏幕左侧移动、右侧转向。更多操作见[游历与操作索引](02-方案/17-六阶段交付与操作索引.md)。

想体验第三人称原型，可在开发地址后加 `?cam=third`；步行时按 `V` 起飞，再按 `V` 请求降落。原型功能尚未完成真实设备与手感验收。

## 一起参与

不需要先熟悉整个代码库。欢迎从一个小问题开始：

- **体验反馈**：哪些地方让你迷路、卡住或觉得不舒服？请附浏览器、设备、操作步骤和截图（如方便）。
- **性能与兼容性**：帮助测试不同显卡、浏览器、手机和触控方式，尤其是低端设备与长时间运行。
- **代码贡献**：修复问题、改善操作与无障碍、优化渲染/资源生命周期、补测试或完善开发文档。
- **设计讨论**：对空间布局、导览、光影、声音或项目方向提出建议。先讨论再大规模实现，能减少返工。

### 提交想法或问题

请到 [GitHub Issues](https://github.com/dengjue/westernParadise/issues) 新建 issue。描述你遇到的问题、期望结果、复现步骤和运行环境；新功能建议可以先说明要解决的体验问题及取舍。暂时没有固定 issue 模板，直接写清楚即可。

### 提交代码

1. Fork 仓库并从 `main` 创建一个目的明确的分支。
2. 开始前阅读 [`AGENT.md`](AGENT.md) 的项目约定；复杂或影响方向的改动，请先开 issue 讨论。
3. 尽量保持改动聚焦，补上对应测试和文档。
4. 本地运行 `npm ci` 和 `npm run verify`，确认通过后提交 Pull Request，说明改动动机、验证结果及尚未覆盖的情况。

`npm run verify` 会执行类型检查、依赖分层和内容检查、lint/格式检查、测试以及两种构建与离线产物断言。当前自动化测试覆盖漫游、输入、音频、渲染预算、第三人称及飞行导航等；自动化通过不等于真实手机或所有设备验收通过。

### 项目边界

项目聚焦**建筑美学、文化空间与静观漫游**。不做宗教仪式、募捐/功德/祈福、教义宣讲、真实寺院或宗教人士背书，也不以宗教人物或圣像设计战斗玩法。公开传播和正式发布前仍需独立合规评估。请勿提交未经授权的素材、个人信息或误导性背书。

## 项目进度

目前已有可运行的园林漫游、四个观景点、第一人称步行、自动游览、光影时段切换、四档画质及第三人称/飞行导航原型；`?cam=third` 另含核心庭园与东侧水院跨区灰盒，并接入原型级 cell 调度。当前并发、预取与驻留值尚未按真机校准，cell 构建仍在主线程，不能视为性能验收或正式流式加载完成。最近一次自动化检查为 **37 个测试文件、223 项用例通过**；严格性能验收、真实手机持续性能和原生后台/锁屏生命周期仍有待完成。项目方向、阶段状态与下一步请看[长期工作计划](02-方案/19-长期工作计划-大世界第三人称与性能验收.md)，具体证据见[性能与设备验收方案](02-方案/18-后续优化-性能收敛与真机验收.md)。

## 开发命令

| 命令 | 用途 |
|---|---|
| `npm run dev` | 启动本地开发服务器 |
| `npm run dev:multiplayer` | 启动仅监听本机的多人 WebSocket 服务 |
| `npm run dev:multiplayer:lan -- <私网 IPv4>` | 启动局域网联机测试入口 |
| `npm run test` | 运行自动化测试 |
| `npm run verify` | 运行完整检查与构建 |
| `npm run build` | 构建多文件站点到 `dist/site/` |
| `npm run build:single` | 构建离线单文件到 `dist/single/index.html` |

项目使用 TypeScript、Three.js、Vite 与 Vitest。源码在 `src/`，测试在 `tests/`；编号目录体现单向依赖层级。`dist/`、`reports/` 和 `node_modules/` 是本地产物，不提交到仓库。

### 本机双人庭院

分别在两个终端运行 `npm run dev:multiplayer` 和 `npm run dev -- --host 127.0.0.1 --port 5173 --strictPort`，然后用两个标签页打开 [联机庭院](http://127.0.0.1:5173/?scene=courtyard&multiplayer=1)。一边用 WASD 走出几步，切到另一边即可看到远端角色。两个角色初始在同一个出生点；关闭一个页面会让对应角色消失。该入口仅用于本机开发，默认站点和离线单文件不会联机。

### 局域网联机

在服务器上运行 `npm run dev:multiplayer:lan -- <服务器的私网 IPv4>`（不要输入尖括号），再用同一局域网的设备打开终端打印的地址。只需开放指定网卡的 TCP `5173` 给可信局域网，不需要开放房间服务端口或做公网端口映射。此入口未加密、无身份认证，测试结束后按 Ctrl+C 关闭。

### 独立局域网测试服（qu3）

开发机运行 `bash scripts/deploy-multiplayer.sh`，自动检查、构建、经 SSH 上传到 `qu3`、切换版本并检查 HTTP 和联机握手。首次部署会安装用户目录内的已校验 Node.js 运行时；部署失败会恢复上一版。有在线玩家时，重启会让他们断开。

**主体验**：[精修极乐世界](http://192.168.100.25:5173/) · [第三人称大世界](http://192.168.100.25:5173/?cam=third)。这两个入口目前为单机。另有[早期小庭院联机原型](http://192.168.100.25:5173/?scene=courtyard&multiplayer=1)，仅用于验证同步，不代表主场景画质。

**双人步行**：[精修大世界地面联机](http://192.168.100.25:5173/?cam=third&multiplayer=1)。两台设备分别进入游历，走出共同出生点即可见到彼此。起飞或退出步行会离开地面房间；回到观景模式再进入游历即可从入口重新加入。验收顺序见 [25 号备忘录](02-方案/25-精修大世界联机备忘录.md)。

服务器只在这个私网地址运行静态站点和房间服务，不运行 Vite。问题排查：`ssh qu3 'journalctl --user -u western-paradise-test.service -n 30 --no-pager'`。服务随 `dj` 的用户服务管理器启动；若主机重启后没有用户登录且未开启 linger，不会无人值守启动。本脚本不修改该系统设置。
